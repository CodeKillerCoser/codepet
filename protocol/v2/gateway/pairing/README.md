# Gateway 设备配对与凭据协议

配对是 Gateway 侧独立的准入模块，不从属于 LAN，也不要求通过已经授权的业务 RPC 调用。messages.schema.json 定义现有配对申请、状态、邀请二维码与凭据撤销对象，bindings.json 记录当前已有的 HTTP 绑定；连接发现、TLS/DTLS 和信令由对应适配器负责。

客户端先获得 Host 的可信身份信息并校验连接绑定，提交本机身份与一次性随机值；需要人工确认时在 Host 批准前只显示 pending，不把它视为已配对。终态与有效期遵守现有流程，接受后保存设备元数据及敏感 credential。后续连接携带凭据并执行 Gateway handshake；撤销凭据应关闭其活动通道，客户端清理本地授权。

历史 SDK 包名 codepet_lan_channel_sdk 和 LanHostIdentity 保留，以兼容已有 App 引用；名字不限制协议归属。现有 wire 中 gatewayUrl、HTTPS 地址和证书摘要等字段保持原约束，不因目录迁移自动变成所有通道的通用字段。云端邀请/信令中尚未迁入本模块的对象仍由已有实现维护，不能将本次目录调整宣称为新增跨通道协议版本。

此 SDK 只生成类型和严格 codec，不负责建立连接、批准设备、保存秘密或调用业务方法。敏感值不应进入日志。客户端可以使用生成的配对 DTO，通信与设备存储继续由 App 的准入层负责。
