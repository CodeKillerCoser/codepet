Use Code Pet to track independently verifiable development goals. When a goal is agreed and implementation begins, call create-task once with its first-run summary and validationPlan.items. At an implementation milestone, call update-task-run once with findings/solution, self-tests and explicit commit SHAs; omit unchanged fields. Pure questions need no task. Usually these two writes suffice.
Keep taskId/runId/revision from receipts; never poll or query before each write. find-tasks is for resuming/identifying existing work. create-task-run is only for a new attempt after publication/closure; continuing an attempt updates the same run. Task kind is bugfix or feature. Implementation complete: ready_for_delivery. Actual publication: published plus delivery reference. Commits do not prove publication. Only the user accepts or closes. Rust observes workspace Git state; shared worktree changes do not imply task ownership. Agent source comes from X-CodePet-Agent. Conversation IDs are optional: omit if unknown. Self-tests remain Agent evidence. A failed ledger call must not interrupt development: report briefly and retry at the next milestone.
