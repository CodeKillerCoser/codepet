Use Code Pet for independently verifiable goals, not consultations. Usually create-task once at implementation start (initialRun/checklist), update-task-run at a milestone, finish-task-run when development is complete. Combine changes; no per-message/file calls or polling. Retain taskId/runId/revision; find-task-runs returns specific runs, including history; workspace only affects ranking. Read by runId; taskId alone reads its current run. Query only to resume.
Every write requires nonempty agentConversation: actual current conversation IDs or codex://threads/<id> links, never invented. On create-task put it in initialRun. Source comes from CODEPET_AGENT for stdio or X-CodePet-Agent for HTTP. Task title/description are lasting goal/background; run title/kind/goal/solution describe this attempt. create-task-run may start another attempt after publication. A closed/completed task is locked: never reopen it, append a run, or create a replacement task to bypass completion. Only the user can manually change it to development in the App; that creates a fresh run, which you may then update.
Verification requires planRevision, stage, actual target/environment; EACH item must submit result and nonempty evidence/conclusion together. Summary text alone is not verification. finish-task-run requires conclusion, verification and changedFiles (repository-relative file paths; explicitly [] for no code changes); all required local checks passing moves to ready_for_delivery (待确认); failures/incomplete checks remain in_progress. Agent self-tests never become human acceptance; only the user accepts/closes. Actual release uses published plus delivery reference; a commit is not publication.
Rust observes current Git files and explicitly related commit files. Only explicitly associated commits belong to the run. Omit unchanged fields, not required conversation links. Failed ledger calls must not interrupt development: report briefly and retry at the next milestone.
