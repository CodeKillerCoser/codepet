# 菜单栏入口与下拉任务面板（历史方案）

2026-11-10 已由[统一顶部吸附](top-edge-docking.md)替代。专用菜单入口、摘要同步与菜单展开状态已删除；以下保留历史设计与排查证据，不代表当前行为。

## 背景

2026-11-08，用户最终明确：展开面板紧贴系统菜单栏下沿，从 Code Pet 自己的头像下方展开，与浏览器无关。早期把“不要遮挡标签”解释为外部窗口避让是错误方向，相关检测和偏移已全部移除。收起仍使用原生菜单栏“角色头部＋短状态＋任务数”，不覆盖系统图标。

## 目标

- 按当前屏幕分流：物理刘海屏在刘海下沿保留收起条并通过 hover 展开；无刘海屏收起时真正隐藏 pet panel，仅保留原生菜单项，由系统自行排布。
- 展开沿用 `NotchPet.svelte`，保留 provider 图标、标题、状态、最近更新时间和消息预览；顶部固定、列表内部滚动。
- 列表中进行中、等待授权和等待输入的任务置顶，其后保留失败等其他非完成状态，最后显示已完成历史；同优先级保持共享数据的更新时间顺序。已完成任务按 agent（providerId）分别堆叠，整个完成区只显示一个“已完成”标题；点击各组首项的 provider 图标只切换本组展开/收起，支持键盘操作，点击顶卡仍可展开本组。
- 同一 Pet Gateway 数据与 Surface 状态机驱动菜单、展开面板、桌面悬浮；保留自定义图片/图集导入。
- 角色可从菜单项或面板拖出；拖回菜单项或原顶部吸附区恢复停靠。

## 非目标

不更换 UI 框架、不新增 UI 适配接口、不修改 Provider 或 Remote Live Update。物理摄像头区域不可显示内容，不能把 notch detection 当成可用的菜单栏空白。非 macOS 沿用既有平台能力。

## 现状理解

`platform/pet_surface.rs` 已使用 NSScreen 安全区与左右辅助区识别物理刘海，几何坐标为 AppKit 点。此前前端拥有 hover 展开状态，原生单独拥有位置和拖动。菜单项与下拉面板是相邻的两块原生表面，不能继续用 webview mouseleave 直接覆盖原生展开状态。

## 实现路径

原生 `platform/pet_menu` 安装系统状态项；新插入菜单项的临时零坐标不得用作锚点，tracking area 重建产生的 Enter 必须再次检查真实鼠标是否位于入口内；头像由当前素材首帧上部裁切为小 PNG，状态由共享任务列表计算，只在变化时更新。菜单摘要不复制任务标题或正文。原生校验 PNG 格式、长度和尺寸，解码前限制分配量。

`Surface` 的 menuBar 表示当前屏幕实际使用菜单路径，而不是平台是否支持菜单。只有无刘海且菜单能力可用时为 true：hover 打开，点击固定，再点关闭；点击外部、Escape 收起。从入口移入面板由原生鼠标命中统一处理。布局仍由 ResizeObserver 测量并携带 revision；原生收到当前 revision 的布局后才显示面板，菜单关闭时直接 orderOut。物理刘海屏优先使用刘海中心及下沿，前端状态机控制 hover/焦点展开，收起条仍可见。跨屏时清理菜单按下、固定和展开状态，前端重置 hover/focus；拖动沿用原生事务，不新建另一套任务状态。

菜单路径的展开中心跟随当前屏的真实菜单项，顶部严格等于菜单项 frame 的底边，不加垂直间隔。读取菜单项的 AppKit frame，不把 tray 物理坐标套到主屏 DPI。只用自身锚点与屏幕工作区约束横向位置和剩余高度，内容超限时列表滚动。物理刘海屏不接受菜单锚点或菜单拖回目标，避免残留菜单坐标覆盖已识别的刘海。

不枚举其他应用窗口，不读取其辅助功能树，不按前台应用变化重新定位。菜单模块只管理自身状态项、鼠标事件与窗口可见性。无刘海屏展开四角采用普通圆角；物理刘海屏保留顶部外圆角。

完成历史的展开状态只保存在 `NotchPet.svelte`，不增加跨 UI 接口或持久化设置。收起最多绘制三层，后层内容隐藏且 inert；展开复用同一任务行。组内变更不改写共享数据，已完成任务再次运行时会立即回到顶部，隐藏顶卡不会误触展开。

## 涉及模块

- `frontend/lib/pet/menu.ts`：当前角色首帧与共享任务摘要同步到系统入口，阻止旧素材异步结果覆盖新选择。
- `PetApp.svelte`、`presentation.ts`、`surface.ts`：菜单模式接受原生展开状态，关闭请求走同一 Surface；桌面模式仍用原有呈现逻辑。
- `src-tauri/src/pet/surface`：统一控制可见性、菜单锚点、高度预算、拖出与拖回。
- `src-tauri/src/platform/pet_menu`：隔离 macOS 状态项、鼠标监视和自身窗口几何；其他平台提供无菜单能力的实现。
- `webcontent-contract.json`：升级至 API 8，避免只替换前端却缺少原生菜单命令。

## 风险与验证

- 隐形窗口挡点击：原生关闭和启动未测量阶段必须隐藏；实机检查标签可点击。
- 入口到面板误收起：UI QA 验证 webview leave 不覆盖 native panelOpen；原生检查移动和外部点击。
- 跨屏/DPI 错位：几何测试覆盖负坐标与缩放；物理刘海和多屏仍需设备验收。
- 自定义角色失效：原导入实现不变，QA 继续使用模拟导入 atlas；菜单复用该素材读取路径，并有内置头像回退。

## 知识沉淀

布局与点击透传规约同步更新：无刘海菜单路径由系统入口负责收起占位，pet panel 仅负责展开内容；刘海路径保留自己的收起状态条。位置只依赖自身锚点与屏幕，禁止重新引入其他应用的几何。2026-11-10 用户报告已识别物理刘海却走菜单定位，修复证据及原始几何见[多屏边界](multi-monitor-bounds.md)。

## 未知项

菜单项拥挤时由 macOS 控制显示，不能保证任意屏幕始终容纳全部状态项。发布前仍需在物理刘海和多屏设备上验收。
