# 悬浮窗口的实时通知与展示框

2026-11-25 输入归属修订：稳定展开后的整个收纳正文区将鼠标事件交给原 App；不再按原窗口拖动自动解除收纳，也不因同步失败删除条目。重新显示和释放入口统一在 Dock，正文不放激活遮罩按钮。被动展开只 raise，显式选择才激活 App。下文早期“遮挡后正文激活入口”是历史行为，当前约束与验证范围见[原生输入归属复盘](../../40-runbooks/hosted-window-native-input-ownership.md)。

## 背景

2026-11-18，用户明确将顶部悬浮窗口划分为“实时通知”和“展示框”。随后截图标注要求去掉展示框导航行，保留通知样式、钉住和现有按钮；Dock 第一项固定为 Code Pet。最新参考当前窗口截图，进一步明确 Dock 自动隐藏，hover 时浮在内容窗口上。macOS 桌宠已接入此布局，原生窗口兼容性按下文的验证范围记录。

## 目标

- 实时通知独立于展示内容，切页和切换应用均不遮住通知。
- 展示框通过一个共用 Dock 切换通知列表和各个收纳窗口，不再显示页签或左右箭头。
- Dock 第一项固定为 Code Pet，默认选中并显示现有通知/任务列表；其他项以原窗口为主体。
- Dock 默认隐藏，hover 后浮在内容上，出现和隐藏均不占用布局高度。
- 延续用户已认可的收起形态：保留顶部条，隐藏下方内容，收纳窗口不进入系统 Dock 最小化。

## 非目标

本次接入限定在 macOS 顶部吸附面板。消息协议、助手任务来源和其他平台的展示规则沿用现有实现。

## 现状理解

`frontend/lib/pet/NotchPet.svelte` 当前把任务内容放进 `DockPanel.svelte`，后者拥有顶栏、正文裁剪、悬停定时器和焦点行为。正文收起后保留挂载并设置 `inert`，见[动效组件边界](../../10-architecture/dock-panel-motion-boundary.md)。因此两区设计可沿用现有容器边界；任务页的业务状态不应迁入动效模块。

原窗口不是 WebView 的子视图。生产窗口页最终需要原生窗口与展示区域协同，约束见[macOS 收纳方案](../../10-architecture/macos-external-window-drawer-proposal.md)。独立 Swift 示例的成功不能直接证明任意外部窗口都能隐藏。

## 交互草图

结构沿用当前截图：紧凑顶栏包含角色、状态、标题、数量、展开箭头和现有按钮；其下显示当前助手消息，展示框承载完成通知堆叠或应用窗口。右侧保留钉住、切换为悬浮和打开主窗口入口。顶栏主体切换展开/收起；通知消息按可用宽度截断。角色素材复用仓库熊猫图集的静态帧，通知和数量为草图示例。

删除“展示框 / 任务列表 / 应用窗口 / 左右箭头”整行导航，释放空间给内容。水平滚动、触控滑动及左右键切换仅在 Dock 接收；应用内部的滚动、文本选择与快捷键交给原 App。通知列表和应用窗口高度保持稳定，切换时 Dock 不移动。草图默认宽度上限 680px，内容高度可调；生产最小尺寸还需根据目标 App 验证。

Dock 改为展示框底部居中的绝对定位浮层，覆盖在内容上，距底边约 12px；不保留独立行或空白高度，显示/隐藏均不触发内容重排或原生窗口扩缩。默认完全隐藏，鼠标进入底部中央约 22px 高的热区时唤出；移到 Dock 内保持显示，离开热区和 Dock 后延迟 260ms 隐藏。热区本身也必须阻止隐藏，避免唤出后闪退。选择菜单打开或 Dock 内有键盘焦点时继续显示；Escape 关闭菜单和 Dock。键盘导航可唤出 Dock。

图标在浮层内排列，当前项有选中底色及指示点。Code Pet 项固定第一位且不可被应用替代，“+”进入窗口选择。同一 App 的多个窗口应按窗口身份区分。选择 Dock 项只切换展示位，不改变实时通知；Code Pet 项回到现有通知/任务列表，不新增第二套消息数据。Dock 的可见性是临时状态，不和顶栏“固定展开”绑定，也不作为持久化状态保存。

建议状态保存 `selectedView`（Code Pet 或窗口身份）、`expanded`、`pinned`。首次默认 Code Pet，新通知仅更新通知区，避免打断当前窗口操作；展开恢复上次选择。切换和收起保留内容状态。原窗口切走或收起时必须先确认已安全隐藏，再显示目标内容；失败时保留当前内容并提供可见反馈，不用系统最小化作降级。关闭或释放最后一个窗口后回到 Code Pet，Dock 中的 Code Pet 和“+”始终可用。

悬停展开/离开收起继续由现有容器处理。生产实现应将原窗口与弹出菜单纳入有效悬停范围；原窗口正在输入、操作菜单或存在模态对话框时，不应因 WebView 失去鼠标事件而误收起。

## 涉及模块

- `NotchPet.svelte`：组织固定通知、共用 Dock 和展示内容选择状态，沿用任务分组与操作。
- `DockPanel.svelte` / `dockPanelMotion.ts`：继续承担容器测量、悬停、裁剪和展开状态；不得依赖具体 App 或任务 DOM。
- `PetApp.svelte`：未来协调原生展示区域和鼠标命中，避免多个逻辑同时写透传状态。
- 原生 Surface 与平台适配层：未来同步窗口展示位、拖动和隐藏状态，调用方通过统一业务接口访问。

## 风险

- 切换手势抢走应用横向滚动：把手势监听限定在 Dock，并用可横向滚动的真实 App 验收。
- Dock 遮挡原窗口内容或消失后仍拦截点击：只为可见浮层、底部热区和打开菜单建立优先命中，隐藏浮层禁用指针事件。实机验收内容点击、滚动及 Dock 往返；WebView 浮层能否覆盖外部窗口仍需验证层级与输入路由。
- 原 App 最小尺寸超过展示位：接入时读取可调整能力和实际尺寸，用小屏及不可缩放窗口检查，禁止仅裁掉不可见的操作。
- 误收起导致编辑中断：验收原窗口内输入、选区、菜单、模态框和 Dock 之间的鼠标移动。
- 原窗口隐藏失败造成桌面露出：原生层读取实际位置与可见状态，失败回滚；覆盖多屏与切页连续操作。

## 草图验证

自动隐藏改版已在本地浏览器验证：首次 Dock 隐藏，底部热区唤出，鼠标移开后 `opacity: 0`、`pointer-events: none`；从 Dock 切到终端再回到 Code Pet；键盘导航唤出；320px 视口中 Dock 和列表无横向溢出。比较隐藏/显示前后的内容区域，宽 648px、高 200px 保持不变；预览外层因滚动有 1px 位移，不作为内容重排结论。已恢复临时视口设置。窗口选择菜单保持显示、便笺编辑保留和真实 App 输入尚未在本版重新人工检查。

静态检查命令 `python3 <visualize-skill>/scripts/render.py <notification-display.html> --check` 通过 JavaScript 语法与静态 DOM 引用检查；文档使用 `git diff --no-index --check /dev/null knowledge/30-domains/pet-window/notification-and-display-layout.md` 检查空白。

草图内“切换为悬浮”仅预览容器圆角变化，“打开主窗口”仅回到 Code Pet 列表示意入口；两者尚未调用生产命令。该次草图验证仅覆盖预览页面。

## macOS 桌宠接入与验证（2026-11-18）

- `NotchPet.svelte` 继续使用现有顶栏、实时任务和已完成堆叠。首次展开显示 Code Pet 列表，选择外部窗口后在通知下方建立展示区。应用内容区优先使用 800 × 560 个逻辑点。顶栏、实时通知和边距单独计算。原窗口采用字符网格时按实际边界显示；应用规定更大尺寸时，只按回读结果扩大相应维度。超出当前屏幕展示空间时提示具体尺寸并尝试恢复原位置和大小。
- `WindowDock.svelte` 在现有正文的底部中央放置热区，悬停或键盘聚焦时显示浮层。按住原窗口标题栏拖入面板并松手后，Dock 为该窗口增加一项。第一项回到通知列表。Dock 内的横向滚轮和左右键可以切换选项。
- `PetApp.svelte` 通过展示区的原生坐标命中控制鼠标透传。Dock、选择器、通知和顶栏仍由 WebView 接收输入。`DockPanel.svelte` 在收起动效前等待窗口停放结果。
- `platform/window_drawer.rs` 接收桌宠的 Tauri 命令。`platform/window_drawer/macos.m` 使用辅助功能接口管理所选原窗口。跟踪拖动开始时命中的原窗口并记录其位置和尺寸；通过实际位移和松手位置确认钉住。收起时优先尝试移出所有显示器，再试单个显示器的下角。释放、桌宠窗口销毁和正常退出时尝试恢复。拒绝移动或调整尺寸的窗口会返回提示。
- 验证命令包括 `npm run test:pet:ui`、`npm run test:pet:motion`、`npx vitest run frontend/lib/pet frontend/PetApp.test.ts`、`npm run test:webcontent` 和 Rust 的 `cargo test --lib pet::surface`。界面测试在生产 Svelte 组件上模拟原生窗口。独立原生检查确认无辅助功能权限时返回授权提示，空集合可以正常复位。本地 Tauri 调试包通过签名校验。
- 真实第三方 App 的输入、浮层命中、菜单、最小尺寸、收起位置回读，以及跨显示器拖动仍需用已授权的测试包逐项验证。

### 窗口重叠、激活与悬停

用户在微信展示区看到了位于微信上方的 Finder。旧实现只根据 AX 窗口位置打开透明区域。现实现记录目标窗口的 WindowServer 编号，将其实际边界与展示区求交，扣除前方遮挡，再用同一组可见矩形控制背景开孔和鼠标透传。整窗被挡时提供激活入口，显式选择或重新展开时抬起目标窗口。宿主移动、目标几何变化和应用切换会触发层级复核。静止时约每 500 ms 补查一次，以覆盖第三方应用漏发通知的情况。性能采样和可见性回归见[原生动效排查](../../40-runbooks/pet-native-motion-flicker.md)。

点击面板 Dock 的图标会激活所属 App 并抬起对应窗口。点击系统 Dock 的应用图标时，从该应用已钉住的窗口中选择最近展示的一项。系统鼠标松手计数用于识别在两次指针采样之间完成的点击。拖入收纳在原生鼠标按下时绑定 WindowServer 窗口编号与边界。松手后仅在该进程内匹配辅助功能窗口。

面板悬停 280 ms 后展开，移出 850 ms 后收起。Dock 热区悬停 180 ms 后显示，离开 700 ms 后收回。固定展开时，Dock 与面板一起保持显示。显式点击收起按钮立即执行。

验证使用 `npm run test:pet:ui` 的模拟原生事件覆盖拖入、固定尺寸、小屏收缩、遮挡后重新激活、系统 Dock 松手和固定状态。`src-tauri/tests/macos_drawer_parking.m` 使用本进程真实 AppKit 窗口验证尺寸和释放，并用构造的窗口顺序覆盖遮挡判定。微信与 Finder 的真实跨进程拖动、键盘焦点和切换瞬间仍需在授权运行的测试包验收。

### 拖入后只有“激活终端窗口”，或提示无法适配展示区

2026-11-18，用户截图显示已选中的终端只剩激活入口，还报告微信和 QQ 音乐在选择后提示尺寸不适配。本机只读的窗口几何数据显示终端为 800 × 559 点。运行时窗口同时可能与小型浮层相交。旧实现遇到任意局部遮挡会关闭整个开孔，AX 尺寸与请求相差超过 1 点则拒绝收纳。截图当时具体是哪个窗口造成遮挡没有确认。

展示时先请求默认尺寸并有界等待 AX 回读，按实际接受的尺寸协商。首次拖入时，前端按应用实际需要扩大面板。原生窗口位置跟随 WebView 调整时，若面板的原生尺寸尚未提交，下一次同步会重试。释放仍恢复拖入前的几何状态。

原生测试用独立的 AppKit 窗口验证最小尺寸 880 × 610、WindowServer 实际窗口编号、角落收起和释放。遮挡回归覆盖局部、全部和终端高度差 1 点。界面测试检查自适应放宽及遮挡区域拦截输入。WKWebView 像素检查覆盖两个开孔和位于中间的不透明区。此次未对微信或 QQ 音乐执行拖入、移动、输入或改尺寸操作。

### 收纳期间拖动原窗口边角

2026-11-19 用户反馈拖动原窗口的边或角后无法缩放。接口 20 的展示同步在 AX 回读尺寸与上次结果不同时重新请求展示区尺寸。接口 21 保留首次拖入的 800 × 560 点默认值，展示期间由原窗口驱动后续缩放。

拖动时，原生层按已收纳窗口的编号读取 WindowServer 几何；松手后使用 AX 回读并对齐最终位置。面板按实测宽高同步增减，最大值按当前显示器可用区域计算。拖动过程中离开面板仍保持展开。切页和收起再展开沿用此窗口的展示尺寸，释放时恢复拖入前的位置与大小。应用自身的最小尺寸仍由应用决定。

原生回归使用独立 AppKit 窗口，包含左上角移动、放大、缩小、超过展示空间后对齐，以及释放恢复。桌宠 UI 回归覆盖 910 × 610 到 680 × 420 点的连续变化、切页尺寸保留和拖动期间的开合状态。原生测试通过写入样本窗口模拟拖动几何，第三方应用实体鼠标手势需另行验收。

## 收起时报“此 App 不支持完全收起”

2026-11-18，用户已进入窗口选择流程并在选择后看到该提示。本机 macOS 27.0 的独立 AppKit 测试窗口宽 441 点。通过 AX 向 1920 × 1080 显示器左右边界外移动时，系统返回成功，坐标回读却显示有 40 点仍可见。向下移动仍保留 32 点高的标题栏。旧版在首次展示前执行完全移出检查，因此这类窗口在选中时就会被拒绝。用户所选 App 的具体名称和实际尺寸未知。

用户接受屏幕下角的极细边缘。现实现根据移动后的实测矩形判断，允许最多一块显示器的底部左角或右角留下一条宽度不超过 1 个逻辑点、高度不超过 64 点的边。移动失败时尝试恢复展示位置并保持展开。切换窗口及自动收起共用同一判断。

原生回归覆盖双屏左右与上下排列、边缘过宽或过高，以及一个真实 AppKit 窗口反复停放、展开和释放。该窗口实测保留 1 × 32 点，没有进入最小化，也没有隐藏应用。实际第三方窗口仍需在目标 App 上验收。可在有图形会话的 Mac 中复查：

```sh
clang -fobjc-arc -framework AppKit -framework ApplicationServices -framework ImageIO src-tauri/tests/macos_drawer_parking.m src-tauri/src/platform/window_drawer/watch.m -o /tmp/codepet-drawer-parking-test
/tmp/codepet-drawer-parking-test
```

### Qt 自绘标题栏拖入时无法识别

2026-11-18 在 macOS 上用 Qt 6.12 的独立 QMainWindow 对照测试。同一个窗口使用系统标题栏时，辅助功能报告 `AXStandardWindow`；使用 `FramelessWindowHint` 时报告 `AXDialog`，在自绘区域命中的是可追溯到该窗口的子控件。旧版在读取尺寸之前就拒绝了后一种窗口。

早期拖入实现从命中控件解析所属顶层窗口。目前按下时记录窗口编号，松手后在该进程已枚举的顶层窗口中匹配实测边界，再检查模态状态与非标准子角色的位置写权限。仍由松手时窗口的实际位移确认拖动。在无边框样本上请求 800 × 560 点，回读为应用要求的 880 × 610 点，可以恢复拖动前边界。`src-tauri/tests/macos_drawer_parking.m` 覆盖可移动的非模态窗口与模态对话框。微信实际暴露的窗口角色与失败阶段仍待该应用的直接证据。

### 拖到桌宠时没有「松手钉住窗口」

2026-11-18，用户在 Tauri 窗口和微信上都没有看到拖入提示。旧版从 WebView 轮询发起按下命中，对起点有 72 点的标题栏限制，且提示位于收起时隐藏的正文。仅验证 Qt 的 AX 子角色与尺寸并未覆盖这些环节。

现在 AppKit 记录按下目标，物理按键首次变为按下可补采样。指针进入面板后检查相同编号的窗口是否移动，提示直接画在面板表层。松手时按事件位置判断投放区域，再请求 AX，避免自绘标题栏的命中子控件或拖动中的 AX 响应阻断反馈。日志中 `pet.window_drawer` 的 `no-source-event` 表示未记录到按下目标，`no-window-movement-at-drop` 表示未确认目标随指针移动，`drop matched window` 表示已匹配，可继续检查展示阶段。

原生测试向事件处理入口投递鼠标样本，在真实 Tauri 和 Qt 无边框样本上，从距顶部 110 点处开始，移动窗口、松手匹配并释放。UI 用模拟指针验证收起态提示、快速松手和位置回读。自动化工具定向拖动另一个独立样本时未观测到全局鼠标事件，未取得跨进程实体鼠标端到端证据。微信的实机结果仍待确认。

## 窗口收纳的代码归属

- `PetApp.svelte` 保存 Surface 状态、桌面任务折叠偏好和鼠标透传。桌面列表跨停靠切换保留折叠，新活动到达时恢复展开。顶部面板的展开、焦点和悬停仅由 `DockPanel.svelte` 驱动 `presentation.ts`。
- `NotchPet.svelte` 决定通知与应用的布局，持有展示区。面板通过 overlay 插槽提供外壳、背景、正文与 frame 节点。`WindowDock.svelte` 用这些节点定位窗口、处理遮挡与收起，调用 `windowDrawer.ts` 定义的带类型命令。展示区默认尺寸集中在同一个模块，重新选择已收纳窗口沿用该窗口协商过的尺寸。
- `platform/window_drawer.rs` 负责 Tauri 调用、坐标换算与原生命令串行化。`macos.m` 保存 AX 窗口身份、还原位置与 WindowServer 可见区域。`watch.m` 拥有通知订阅和主 RunLoop 合并逻辑，经 `watch.h` 暴露接口。鼠标事件提供松手坐标，避免 IPC 执行时光标已离开系统 Dock。
- 释放与停靠共享背景封闭顺序。释放成功后才移除 Dock 条目，释放失败时保留重试入口。用 `npm run test:pet:ui` 注入延迟和失败，检查恢复中的窗口已停止透传、失败后仍能重新显示和释放，并覆盖桌面任务折叠跨视图保留的行为。

本轮架构清理后，全量前端 201 项、Rust Surface 16 项、webcontent 11 项通过。顶部 UI、逐帧动效、完成任务堆叠以及 macOS 原生通知样本通过，桌面程序和原生 QA 示例完成链接。UI 用例分别挂起鼠标透传设置和释放请求，验证前者完成后才执行后者。原生样本在锁屏期间验证了保存松手坐标、一次性消费和移动通知。这轮未进行亮屏后的第三方窗口拖动与桌面合成像素复测。
