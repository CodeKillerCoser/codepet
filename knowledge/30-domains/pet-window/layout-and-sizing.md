# 布局与尺寸

## 当前尺寸模型

桌宠窗口在 `frontend/PetApp.svelte` 中使用预设逻辑宽高。用户手动缩放被禁用，但应用仍会调用 `setSize()`，确保窗口 frame 可预测。

当前逻辑宽度为 320px（原为 360px），任务区最高 320px（原为 368px）。CSS 宽度随容器收缩，卡片使用组容器的完整宽度；宠物传入的显示 scale 为用户设置值的 90%，仍受头像组件最小尺寸保护。保持预设窗口 frame，不以折叠内容高度反复调整原生窗口。

分组收起时使用 `perspective: 600px` 和负 Z 位移呈现前后层次，每层垂直错位 7px、深度递减 18px；为后层预留底部空间。展开后隐藏后层装饰，在组头下显示任务卡片。

任务卡片内容不应依赖固定卡片高度。回复编辑器和 footer 间距需要在卡片中自然撑开。

## 已知 UI 约束

- 只有一个任务卡片时，不应出现无意义列表滚动条。
- 操作按钮存在时，footer 间距仍需可见。
- 回复模式可以覆盖到桌宠窗口区域上方，但控件必须保持可触达。
- 文本不能覆盖卡片 footer 或按钮。
- Markdown 消息高度限制在独立的 120px 滚动区域，不能对原始 Markdown 截断后再解析；长代码、表格不得扩大卡片宽度。
- 分组头是鼠标透传命中区域的一部分；原生 `details` 收起后，隐藏卡片通过可见性检查排除。

## 验证

- 人工检查单卡、多卡、回复模式、审批模式和收起任务列表。
- 布局变更后运行 `npx vitest run frontend/PetApp.test.ts frontend/lib/activity.test.ts`。
