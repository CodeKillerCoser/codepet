# 布局与尺寸

## 当前入口与面板位置

macOS 停靠统一使用自己的顶部单条窗口，不再使用系统菜单入口。默认水平居中，横向拖动保持吸附，向下拖出恢复悬浮，拖回屏幕顶部任意横向位置重新吸附。全部位置使用顶部外圆角；窗口黑色轮廓从屏幕顶边起，与物理刘海连续融合。只有内容的纵向安全区随刘海重叠变化，头像与文字避开摄像头。展开面板固定顶栏并沿用现有任务列表。原生契约 API 9，详见[统一顶部吸附](top-edge-docking.md)。非 macOS 保持既有浮窗能力。

## 当前尺寸模型

尺寸由 `frontend/lib/pet/sizing.ts` 根据原生 Surface 返回的当前逻辑工作区计算。macOS 使用 AppKit 点，其他平台扣除 DPI；不能使用会随桌宠窗口变化的 `vw/vh` 计算目标宽度。跨屏、显示缩放与工作区变化经 revision 更新后重新测量。

用户试用后指出直接按屏幕 44% 宽、60% 高会在 4K 上占用过大。因此当前使用缓慢增长：宽度基准乘 `sqrt(屏幕宽 / 1440)`，高度基准乘 `sqrt(可用高 / 860)`，再限制到紧凑范围。大屏占比随屏幕增加而下降。

| 区域 | 当前尺寸规则（逻辑单位） |
| --- | --- |
| 顶部收起 | 自然宽度，上限基准 200，随屏幕变化限制在 160–260；刘海/顶部条高基准 24，限制在 22–26；有刘海重叠时额外计入原生安全区高度。 |
| 顶部展开 | 宽基准 440，限制在 340–640；高度按内容收缩，上限基准 340，最多 440。 |
| 桌面浮窗 | 宽基准 280，限制在 240–360；总高度预算基准 360，最多 440，扣除角色、操作栏和边距后分配任务滚动区。 |
| 角色 | 宽基准 80，采用横纵缩放因子的较小值，限制在 64–104 后应用用户大小偏好。头像随条高变化，保留完整帧宽和上部裁切。 |

全部尺寸再受当前屏幕可用范围限制。上述值是可读下限与大屏上限，不是所有屏幕共用的固定目标。字体和点击目标保持可读。原生按当前屏幕校验布局，数值安全限制不作为正常布局目标；webcontent 契约为 API 9。

`frontend/lib/pet/surface.ts` 用 ResizeObserver 测量 `.pet-content` 的自然高度、角色中心及尺寸，去抖 60ms 并携带 revision。桌面保持角色中心屏幕位置，内容超出工作区才钳制；顶部保持停靠区下缘与面板中心。桌面外层只保留顶部 10、底部 12 的装饰余量，不能按最大任务区预留透明高度。拖动期间任务收起，原生保留鼠标抓取偏移。状态条与列表共用容器，只有列表滚动，操作提示也计入高度预算。

桌面 UI 的 `PetActivityGroups.svelte` 按等待交互、进行中、已完成分组。收起时最前方直接显示真实任务气泡，最多露出两张后层气泡；使用 `perspective: 600px`，每层垂直错位 7px、深度递减 18px，并预留底部空间。点击顶层气泡或组按钮只展开本组，组按钮可再次收起。各组展开状态独立。

分组仅改变排列，不改变气泡的标题、消息预览、来源、状态和时间。运行中气泡继续使用个性化背景（含渐变）、边框色、边框跑马灯、背景呼吸和动画时长；收起和展开使用同一份卡片与配置。变换施加在外层 slot，避免干扰卡片动画。

任务卡片内容不应依赖固定卡片高度。标题、消息与 footer 需要在卡片中自然撑开。

顶部 UI 独立使用 `NotchPet.svelte`：收起使用紧凑状态条，展开后顶栏与列表共享同宽容器；仅列表内部滚动，顶栏与动作保持可见。所有顶部位置均绘制外侧圆角，左右各 6px 装饰边距容纳该装饰。`topInset` 仅控制内容避开摄像头所需的顶部黑色安全区；`physicalNotch` 不再决定样式或交互分支。不预留整屏透明区域。面板本身参与鼠标命中，透明区域仍透传；见[两套 UI 与共享状态](two-views-and-shared-state.md)。

菜单下拉列表将进行中、等待交互等任务放在上方；`completed` 与 `interrupted`（已取消）一起进入“已完成”历史，按 `providerId` 分组，组顺序及组内顺序沿用共享数据的更新时间顺序。整个完成区只显示一个“已完成”标题及总数，不重复展示 agent 分组标题。每个 agent 分组拥有独立的左侧图标列，右侧为任务内容列；收起和展开都只渲染一个 provider 图标，作为展开/收起按钮，提供 `aria-expanded`、`aria-controls` 和键盘操作；点击顶卡也可展开本组，隐藏任务不能误触展开。组内任务不再重复显示 Agent 名称胶囊，保留各自的状态与更新时间，已取消任务仍标记“已取消”。已完成或已取消任务重新运行时立即移出完成历史；某个组消失后清理其展开状态。未知 provider 使用来源名称或原始 ID，不按显示名称合并。

2026-11-09 用户试用后将顶部对齐调整为标题行中心线对齐，并要求间距略小于外层 padding。`NotchPet.svelte` 展开容器四周保持 12px，顶栏头像与摘要仍垂直居中；任务图标边长等于头像高度，图标、标题、状态、时间和 agent 标签沿标题行垂直居中，图标到标题区域、标题到消息均为 8px。窄屏换行时图标保持对齐第一行标题。完成任务只有右侧标题与消息区域带有轻微背景，图标留在外面。背景使用黑色与 `gray-2` 混合，移除整圈边框；2026-11-10 按用户圈选将黑色占比从 70% 降为 20%，略微提亮任务内容背景，收起顶卡和展开各项保持一致；只在收起的后层保留低对比度底边，表达堆叠而不强化卡片感。展开后沿用相同的弱背景。每组最多两层后卡，采用 600px 透视和每层 -18px 深度；2026-11-10 用户截图显示后层过暗、露出过少，将顶部任务组的每层垂直错位从 7px 增至 11px，后层改为 gray-3 背景与 gray-6 底边，最底层略暗。后续按用户要求仅为堆叠顶层增加 1px gray-4 内描边，让轮廓略微突出；展开项与单项不增加描边，内描边不影响测量尺寸；卡片背景与内容容器边界一致，内边距统一为四周 6px，取消背景原先向上和向左的负偏移。图标至卡片外沿为 2px，配合左内边距保持图标至文字 8px；图标随标题行下移 6px 以保持中心线对齐。关闭按钮仅在 hover/键盘聚焦时预留标题行位置，默认时间右侧不留额外空位；底部预留使用同一偏移变量计算，避免层叠超出内容测量。后层等高且不可聚焦；只有一项时没有虚假后层。展开后保持同样的卡片布局，列表滚动预算不变，顶栏固定。

`scripts/pet_notch_ui_qa.mjs` 验证四边 padding、顶栏居中、任务图标尺寸及标题/状态/时间/agent 标签的中心线、内容列边缘、8px 图文与标题/消息间距、操作边界及唯一完成标题；覆盖 agent 图标独立点击/键盘展开与收起、单组移除后状态清理、隐藏顶卡、任务恢复运行、单项和空列表、280px 窄屏及多种工作区尺寸，全部通过。高度预算扣除容器内边距及顶栏到列表的间距，列表仅纵向滚动；保留 `min-width: 0` 与 `overflow-x: hidden`，避免 WebKit 因堆叠变换出现横向滚动条。示例截图位于 `artifacts/pet-notch-qa/agent-stacks.png` 与 `agent-expanded.png`。完整 `.11` App（包含此前 `.10` 的居中与间距调整）构建成功；浏览器 QA 已验证 8px 间距、标题行中心线、弱背景及去边框后的收起/展开效果。Mac 仍锁定，无法切换运行版本或检查本轮原生截图，当前仍运行 `.9`，该项待解锁后验证。此前 `.9` 的原生预览已确认图标开关互不影响。卡片底部装饰计入内容高度，避免内容可容纳时仍出现纵向滚动条。

## 桌面 UI 约束

- 正常无活动时不渲染任务区和“暂无任务”气泡，只保留桌宠；真实连接失败仍显示错误提示。
- 只有一个任务卡片时，不应出现无意义列表滚动条。
- 操作按钮存在时，footer 间距仍需可见。
- 文本不能覆盖卡片 footer 或按钮。
- Markdown 完整解析后，在桌宠气泡内裁剪为一行预览；展开本组也不出现消息详情或内部滚动区。长代码、表格不得扩大卡片宽度。
- 组按钮和最前层气泡参与鼠标透传命中；收起的后层使用 `inert`，不能获取焦点或参与命中。关闭按钮独立处理点击，不触发分组展开。
