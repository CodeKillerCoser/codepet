# 任务抽取的正文与时间边界

## 适用范围与原因

适用于 Codex 活动记录派生的任务语义抽取。用户于 2026-09-10 明确要求只抽取用户消息与 AI text，且只使用最近两天。工具输出会混入执行日志、委派输入及非用户任务，完整历史会扩大成本并污染当前任务边界。

## 约束

1. 输入仅接受原生 message 的 user/assistant 正文内容块；排除工具调用、参数、结果、委派工具正文、reasoning 和重复事件消息。
2. 按消息原生 RFC3339 时间戳判断滚动 48 小时窗口，包含下边界；缺失、无效或未来时间排除。不得使用线程创建时间或文件修改时间补齐消息时间。
3. 旧线程可以贡献近期追加消息；重叠上下文也必须在窗口内。不得因近期上下文不足补入完整历史。
4. 来源层、任务调度、待分析计数和 Claude 执行入口共同守住边界。没有合格待处理消息时不得消耗后台批次或调用模型。
5. 工具记录可用于确定性的谱系关系核验，但其正文不能转换为语义抽取消息。Fork 继承前缀可浏览，不再次抽取。
6. 保留输入 evidence 和抽取窗口元数据，以便证明每个任务的来源。已有任务短摘要可用于去重，不能取代原始消息证据。

## 验证

运行 `cargo test -p codepet-task-lineage`，覆盖 48 小时内外边界、未来/未知时间、工具正文排除、长旧历史后的新增消息、Fork 继承和后台空队列预算。修改来源适配或输入构建时必须保持这些回归。
