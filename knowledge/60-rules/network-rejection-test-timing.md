# 断开类网络测试不要假设发送一定成功

## 规则

当测试预期服务端拒绝帧并断开时，允许拒绝在发送阶段或接收阶段被观察到。限定可接受错误，并继续检查连接终止与服务端会话释放；不能以忽略所有发送错误代替验收。

## 适用场景

LAN/WebRTC 的超限消息、非法帧和主动拒绝测试，尤其是跨平台 TCP/TLS 集成测试。

## 反例

发送 300 KiB WebSocket 帧超过服务端 256 KiB 限制后，先对 send 调用 unwrap，再等待关闭。服务端可以在解析长度后提前断开；Windows 会在 send 返回 ConnectionReset，导致正确拒绝也被判为失败。

## 推荐做法

为发送设置有限超时。正常发送完成或明确的远端关闭类错误均可进入关闭验证；其他错误仍失败。随后验证会话计数归零，并保留正常连接、身份和后续请求的断言，防止“服务端总是断开”也通过测试。
