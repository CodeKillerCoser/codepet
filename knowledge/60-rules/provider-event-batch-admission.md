# Provider 事件包装层的批量接纳

## 规则与适用场景

包装 `ProviderEventSink` 的生产转发层必须保留下游 `publish_batch` 的整批接纳和顺序保证。增加日志、用量、活动等旁路处理时，不得无意继承逐条发送的默认实现。

## 反例

只实现 `publish` 会把完整扫描拆成大量单条队列条目。队列满时前缀已经发出，末尾的就绪通知丢失，扫描不断重试，最终表现为能力不可用和列表重复刷新。

## 推荐做法

提取旁路处理函数，在单条与批量入口复用。批量完成旁路处理后只调用一次下游 `publish_batch`，原样返回错误。旁路写入必须可以安全重放，因为下游拒绝后调用者可能重试。

## 验证方式

用超过队列条目上限的批次穿过真实包装层，检查未拆分、顺序不变、拒绝无部分输出、排空后重试成功。另测旁路功能在批量和重复事件下仍然正确。
