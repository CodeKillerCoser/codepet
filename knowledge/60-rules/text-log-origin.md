# 文本日志格式与来源上下文

## 规则

CodePet 桌面与 Remote 应用日志只持久化一种 UTF-8 文本格式：`年月日 时分秒.毫秒+时区 pid thread 级别 文件:行号 [模块] 内容`。导出直接打包同一批 `.log`，不要再写 JSON/JSONL 副本或另做一种摘要日志。

## 适用场景

普通应用日志、RTC、trace、异常和导出。网络协议 JSON 和数据库并非日志，不能因本规则改变业务协议。

## 反例

只输出事件 JSON，漏掉 PID、线程及源码位置；把 JSON 塞进 message 再编码；在后台写盘线程才采集线程和时间；把 Dart isolate 名称当作 OS 线程；为旧日志猜文件和行号。

## 推荐做法

在生产日志时采集真实 PID、系统线程、时间与调用位置，然后再排队写盘。Rust 包装函数传递 `#[track_caller]`；Dart 平台调用集中于诊断适配器，同步 FFI 读取实际线程，调用栈跳过日志包装层。缺少字段用 `-`，不能用文件写入时间或输出函数位置代替。

时间统一 UTC，明确 `+00:00` 和毫秒；级别使用 DEBUG/INFO/WARN/ERROR。关联 ID 与事件字段用键值文本，嵌套数据展开路径。控制字符清洗，堆栈缩进续行，沿用脱敏和轮转。旧 JSON 日志升级时转换，保持过期时间；用户提供的原始文件不得覆盖。

## 来源

2026-11-06 用户反馈日志缺少标准来源字段，随后明确要求只保留文本、不写 JSON。见 [WebRTC 诊断日志](../40-runbooks/webrtc-ice-diagnostics.md)。

## 验证方式

实际写盘并解压导出，断言每条前缀、真实调用文件行号和跨线程来源，不只测试字符串模板。验证 ZIP 没有 JSONL/重复摘要，转换旧日志不破坏保留期，控制字符不产生伪造行，敏感值不进入文件。AOT/Release 必须验证符号信息；若启用 split-debug-info、混淆或更换运行时，不以 Debug 测试代替发布验证。
