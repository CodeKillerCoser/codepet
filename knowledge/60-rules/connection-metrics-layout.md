# 连接统计的紧凑布局与数字稳定性

## 规则

首页、对话标题中的连接通道、速率和传输总量靠起始边紧凑排列。实时数字使用等宽数字特性，并为数字与单位分别预留固定宽度；一次刷新不得因位数或单位变化推动相邻项目、改变换行位置。宽度按当前字体与系统字号计算，不能以强制缩小文字替代无障碍支持。

## 适用场景

CodePet Remote 的 `ConnectionTrafficView(compact: true)` 及其他每秒更新的标题统计区。首页保持在列表外，跟随选中设备；对话页的数据来源仍为该对话的设备连接。

## 反例

直接在居中的 Wrap 中显示变长字符串：从 `9 B/s` 变成 `10.0 KiB/s` 时，各段占用宽度和整组起点同时改变。仅启用 tabular figures 无法解决数字位数、单位长度变化；把对话统计塞在 Provider 图标和展开按钮之间又会过早换行。

## 推荐做法

- 图标表达上传/下载方向，总量省略“累计”，读屏标签保留完整含义。
- 数字右对齐、单位左对齐，两者分别预留宽度。紧凑数字最多四个字符，小于 100 时保留一位小数，四舍五入越界时用整数；详情保留原有精度。
- 统计行使用标题区的完整宽度，常规字号优先一行；窄屏或大字号自然换行，禁止横向溢出。首页用明确的起始边对齐，避免父 Column 将收缩的统计组件居中。
- 保留局部每秒刷新，不能为布局修改重建会话列表、改变传输计数或触发测速。

## 来源

2026-11-07 用户反馈首页居中且松散、对话页频繁换行，以及数值变化时左右抖动。检查发现原紧凑组件使用变长文本，首页父布局居中，对话统计可用宽度又被图标占用。

## 验证方式

Remote 的 `test/home/connection_traffic_view_test.dart` 比较跨位数、跨单位更新前后的矩形位置，覆盖窄屏、大字号、读屏标签及断线隐藏；首页和对话测试覆盖滚动、设备切换、返回按钮和元数据展开。运行这三个文件共 82 项通过。Roboto/CJK/Material 图标的实际组件渲染已检查 320/360/393px；不将本地渲染等同于手机安装验收。
