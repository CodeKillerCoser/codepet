# 界面层级与视觉重量

## 规则

内容以统一字体层级、留白和对齐组织。慎用卡片与阴影，两者不能叠加；边框使用主题中性灰阶，不使用纯黑。展示与操作共享入口，常见动作优先使用明确图标并提供可访问名称。

## 适用场景

主窗口内容、Task 看板/表格、任务执行概览、全局侧栏和表单。字体数值只定义在主题中；紧凑桌宠可以复用既有 primitive 尺寸，但不能在组件里写死字号、字重、行高和字距。

## 反例

每段内容都套边框和阴影；状态以一种标签展示，再旁置“标记完成”“退回开发”按钮；已经能用占位说明的筛选框重复增加标签；每行重复不提供区分价值的小字；组件各自用 12/13/14px 拼出字体层级。

## 推荐做法

- 主标题、二级、三级、正文、备注使用 theme 的 title/section/subheading/body/caption 字体。主题切换必须保留层级和主窗口字体族。
- 字重统一为正文400、强调500、标题600，使用 heading/content/emphasis/control/active 语义别名；strong/b/th 不能沿用浏览器默认700。结构标题不能小于其子标题，实际计算样式要验证到 App 外框及全局侧栏，不只搜索是否用了 token。
- 同组字段使用4–8px紧凑间距，独立分区使用28px；先让标签、第一行文字和图标对齐，再处理换行。验收方式/预期/结果成对排列，极窄屏再纵排；时间线保留节点、时间列和正文列，长事件可展开完整阅读。
- 任务状态使用 TaskStatus；可操作的当前执行由 TaskRunStatus 将状态和菜单放在一起。历史状态只读。完成仍调用原人工 close-run；恢复开发通过原表单新增执行，不能改写旧验收或绕过完成锁。
- 工作区状态由 TaskWorkspaceStatus 复用同一组 Git 语义图标，不能把推送状态当成发布状态。验收继续使用空心圆、独立通过勾与失败图标。
- 任务执行用平面列表和细分隔线；看板卡片保留轻边框，不加阴影。删除重复摘要与固定说明，错误、未核实来源、历史只读和真实未知状态仍要可见。
- 关闭、删除、刷新、收起等动作使用 Lucide 图标，aria-label 和必要 title 说明功能；确认类按钮使用短文案。状态菜单支持键盘、Escape 只关闭菜单，取消编辑返回原状态入口。

## 来源

2026-11-25 用户对任务页视觉重量的反馈及补充边框约束；实现说明见主题 token 模型和任务记录模型。

## 验证方式

字体约束由 frontend/styles.test.ts 覆盖所有生产 CSS/Svelte style；任务 UI QA 覆盖明暗、宽窄、四列/表格自动切换、状态菜单键盘与历史只读。原生隔离账本验证完成/恢复保留旧执行。共享主题还需检查设置弹窗和桌宠尺寸，禁止将布局样例写成生产任务验收结果。
