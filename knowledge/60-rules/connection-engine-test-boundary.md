# 连接引擎必须能够脱离业务独立验收

## 规则

通道策略、健康观测和流量计数不得 import Flutter、Gateway/Provider DTO、平台 API 或业务控制器。平台与业务经适配器提供输入和交接结果；核心测试必须用标准 Dart 单独运行。

## 适用场景

设备首次连接、网络变化、前后台恢复、手动重连、通道升级及多设备资源预算。各场景只更新 TargetSpec，不在引擎中添加场景分支。

## 反例

把 socket 指针换掉便宣布在线，会丢失订阅、留下两条可写通道。把超时当作底层资源已释放，会在 ICE/close 卡住时无限分配。用 mock 压测的微秒数声称真实 IPv6/TURN 性能，会得出错误结论。

## 推荐做法

核心负责候选优先级、代次隔离、退避、预算和固定窗口统计；桥接负责身份校验、业务排空、Host 权威提交、事件续订。恢复排队优先于健康优化；原生未结束的操作保留许可，清理结果不明则隔离并记录。未知结果的业务写操作不自动重放。

[连接引擎设计](../10-architecture/connection-engine.md) 与 [独立及双端验收](../40-runbooks/connection-engine-verification.md)。

## 验证方式

独立 `dart analyze/test`，1,000 次资源清零循环，混合多设备压力脚本，以及 App Bridge/Host 原生 WSS/RTC 交接测试。新 IO 适配器必须额外证明取消、迟到、close 失败和实际网络背压行为；纯核心通过不替代真实手机切网测试。
