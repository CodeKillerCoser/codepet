# 本机任务 MCP 的传输与账本边界

## 规则

默认任务 MCP 是 App Rust 后台的本机 HTTP 服务；前端只展示配置与账本。人工操作与 Agent HTTP 工具共享同一个活动 Ledger，前端不可代理 MCP 请求或负责服务存活。

## 适用场景

任务接入配置、App 启停与数据目录切换、HTTP 读写及发布验证。

## 推荐做法

服务固定监听 127.0.0.1，验证 Host/Origin 与自动持久化的本机凭据；端口占用或启动失败时不得仍展示可用 URL。App 托管启动与退出，关闭业务页面不停止服务。切换数据目录需重启后统一生效。配置从实际运行服务生成，用 url/http_headers 替换原 command/args；旧 stdio 仅兼容。

保持 tasks_find/tasks_save 两个工具与紧凑回执，不因 HTTP 增加查询、轮询或任务维护步骤。Agent 自测不得变成人工验收。开发自己也应在关键节点使用 MCP 登记；当前会话未加载工具时应明确说明，并通过已有 MCP 入口补记，不能将“提供了工具”当成“已经登记”。

## 来源与验证

[本地任务 MCP 接入与验收](../40-runbooks/codepet-task-mcp.md)。2026-11-24 用户指出默认暴露仍是 stdio 且本轮漏登记，促成此约束。

运行任务 crate 测试、`scripts/task_mcp_http_smoke.mjs`、stdio 兼容测试和原生任务 UI 验收。官方 SDK 客户端须可初始化、枚举和调用；原生验收须证明 HTTP 写入能被同一 App 的生产 IPC/界面读取。测试使用隔离数据，真实开发任务另作登记；不得拿样本通过冒充真实问题验收。
