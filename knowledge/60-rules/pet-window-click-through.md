# 桌宠透明区域事件透传

## 规则

透明桌宠窗口的非命中区域必须使用窗口级鼠标事件透传，不能只依赖 CSS `pointer-events: none`、移除拖拽层或前端事件吞吐来表现为“不响应”。

## 适用场景

修改 `frontend/PetApp.svelte`、桌宠窗口尺寸、透明背景、拖拽命中区、宠物图片渲染、任务卡片交互或 Tauri window capability 时适用。

## 反例

让透明区域不触发拖拽，但窗口本身仍接收鼠标事件。用户看到透明区域，却无法点击或滚动其下方应用，尤其在固定大窗口高度下会形成大面积屏幕事件拦截。

## 推荐做法

通过统一 Surface 平台接口读取窗口内逻辑鼠标坐标；macOS 的 AppKit 点坐标不能与 Tauri 物理像素混算。只在任务卡、操作按钮、宠物不透明像素和顶部可见面板等命中区域内恢复 `setIgnoreCursorEvents(false)`，其余区域设置 `setIgnoreCursorEvents(true)`。新增或调整 Tauri JS window API 时同步检查 `src-tauri/capabilities/default.json`。

图集命中必须读取渲染组件公布的当前行、列和帧边界，不能将整张图或第一帧当命中区域。静态图片 `object-fit: contain` 产生的留白必须扣除；装饰性情绪叠层不应扩大鼠标拦截区。实现统一放在 `frontend/lib/pet/hitTest.ts`，不再从旧像素 DOM 或 CSS 变换猜测位置。

透明事件透传与拖动边界必须分别验证。原生窗口应贴合实际布局并保留有限装饰边距；不能用透明区域可透传来证明大窗口没有问题，因为整窗工作区限位仍会让透明留白提前触顶。调整内容高度应保持桌宠角色锚点（停靠时保持停靠区下缘），并在低高度工作区缩小任务滚动区。

## 来源

用户反馈：透明区域在 app 内不响应，但事件不会透给其他窗口；需要的不是禁止拖拽响应，而是真正透传。历史提交 `754581a fix(pet): 让透明区域鼠标事件穿透` 也说明该行为曾作为 Bug 修复出现过。

## 验证方式

运行 `npx vitest run frontend/PetApp.test.ts frontend/lib/petHitTest.test.ts`。人工验证时在 Windows 和 macOS 上检查：透明区域可点击下方窗口，任务卡/按钮可点击，宠物不透明像素可拖动，宠物透明像素尽量不拦截下方窗口。

图集和图片留白另运行 `npx vitest run frontend/lib/pet/hitTest.test.ts`；`scripts/pet_module_ui_qa.mjs` 使用真实素材验证 alpha 和原生调用边界，但不能替代操作系统实测。

内容高度和拖动边界另运行 `scripts/pet_window_frame_ui_qa.mjs`，覆盖单卡/无任务、展开收起、顶部边界和不同 DPI；原因与证据见 [透明留白阻止上移](../40-runbooks/pet-window-transparent-frame-blocks-drag.md)。


## 刘海与拖动补充

原生拖动事务期间禁止工作区强制限位，也不能切回鼠标透传，否则无法进入吸附带或丢失松手。前端 CSS 布局改变后必须测量角色锚点，原生根据 revision 接受新布局；不得再由前端和原生分别 setPosition/setSize。拖动结束或取消后恢复透传检查。

同模式横向拖动应保留抓取时的展开状态和有效布局；不能仅因 dragging 改变就重置展开、隐藏窗口或强制重测。hover 延时在按下拖动源时取消，拖动中进入/离开与焦点变化不能改变展开状态。展开动画不要逐帧改变测量高度；优先裁剪揭示或不影响布局的动画，并尊重减少动态效果。回归覆盖展开/收起两种拖动、延时前按下及原生 frame 连续可见，见[统一顶部吸附](../30-domains/pet-window/top-edge-docking.md)。

顶部模式以实测整条 header（含 padding）作为拖动区域，并单独传入 Surface；不能用头像框代替顶栏范围，也不能让任务列表参与拖动。按钮仅在超过移动阈值后切入拖动并屏蔽随后 click，正常点击与键盘操作仍有效。不得对顶栏做从零高度开始的揭示或整体淡入；共享内容平移时允许按当帧背景边界裁剪前景，但必须保留已有顶栏的完整可见区域；尺寸同步不能延迟到新顶栏已被旧 frame 裁切后。通过顶部 UI QA、Surface 测量与原生命中测试验证，来源为 2026-11-10 用户标注的整条顶栏与头像闪烁截图。

新增回归：Surface 几何/状态测试、前端旧布局回复测试，以及顶部→悬浮→顶部的原生拖动验收。实现与证据见[接入实施记录](../30-domains/pet-window/notch-docking-design.md)。

顶部状态条与下拉内容是一个完整命中区域，不能只命中里面的按钮，否则 hover 会穿过列表空隙。头像裁切后 alpha 检测必须同时受头像外框限制，不能让裁掉的身体扩大命中区。`scripts/pet_notch_ui_qa.mjs` 覆盖两套 UI 的展开、焦点与尺寸。

展开宽度与收起宽度可以不同，但展开后的当前活动栏必须与列表共用容器；只允许任务区滚动。外侧圆角需要有计入内容测量的有限边距，不能超出原生 frame 被裁掉。头像视口不要小于渲染帧宽度，以免左右耳朵被切掉；固定上部裁切仍不等同于任意图片的头部识别。

顶部外圆角用于所有顶部吸附位置。`physicalNotch` 只参与原生几何；内容通过 `topInset` 避开摄像头，黑色背景从屏幕顶边连续填充。不得重新按屏幕类型切换菜单模式或圆角。来源为用户 2026-11-10 确认的统一视觉图；`pet_notch_ui_qa.mjs` 验证两类屏幕和移出刘海后的轮廓一致，真实刘海/混合 DPI 仍需设备验收。


屏幕比例布局必须从原生当前显示器的逻辑工作区计算；禁止用桌宠自身 viewport 的百分比推导下一次原生窗口尺寸，否则 resize 会反馈到自身尺寸并反复缩放。尺寸预算是上限，实际高度必须按内容收缩，角色和操作栏空间先于滚动区保留。验证顶部 QA 的多屏尺寸矩阵、窗口 QA 的混合 DPI 与稳定 resize 次数；依据见 [布局与尺寸](../30-domains/pet-window/layout-and-sizing.md)。


## 未激活窗口交互

后台交互是透传的独立回归项：pet WebView 必须接收未激活时的首次点击，NSPanel 必须接收鼠标移动；不要通过激活应用或强抢键盘焦点修复 hover。失焦时可复用 Surface 原生光标检测同步进入/离开，只在状态改变时派发，保留 Escape 和延迟收起语义。验证 `pet_notch_ui_qa.mjs` 的无 DOM 鼠标事件场景及 native smoke 中的真实 WebView/Panel 标志；仍需实机验证首次点击和拖动。来源：[后台鼠标无响应复盘](../40-runbooks/pet-background-pointer-unresponsive.md)。

## 系统菜单栏入口补充（历史）

以下为已移除的菜单方案约束；当前行为见[统一顶部吸附](../30-domains/pet-window/top-edge-docking.md)，不可据此恢复旧菜单入口。

macOS 无刘海且菜单能力可用时，收起态必须由 NSStatusItem 占位，详情窗口关闭时真正隐藏；禁止把固定居中的透明/黑色覆盖窗口直接移到菜单栏坐标。面板顶边必须紧贴状态项下沿，不预留透明连接区。native panelOpen 是菜单模式的展开状态来源，webview mouseleave 不得自行收起。

`menu_ready` 仅表示平台能力，不能决定所有屏幕的布局。当前屏 `physicalNotch=true` 时必须优先使用刘海锚点、保留收起条并恢复前端 hover 展开；菜单坐标、隐藏和点击固定逻辑不得覆盖刘海模式。跨屏时重置两侧交互状态，菜单锚点只接受当前无刘海屏的坐标。来源为 2026-11-10 用户报告：安全区已识别刘海但仍走菜单定位；回归使用报告原始几何，同时覆盖拖出/拖回/取消和两种呈现状态切换，详见[多屏边界](../30-domains/pet-window/multi-monitor-bounds.md)。

展开位置仅由自身菜单项和屏幕边界决定，不读取浏览器、其他应用窗口或 AX 工具栏，不添加避让距离。超高面板缩短列表预算，不能改变顶部锚点。位置回归须比较实际 AppKit frame 顶边与菜单项底边，DOM 尺寸和可见性通过不足以证明位置正确。来源为用户 2026-11-08 明确澄清“和浏览器没关系，我们管理好自己的窗口就可以了”；见[菜单面板定位复盘](../40-runbooks/menu-panel-displaced-downward.md)。

NSStatusItem 插入或恢复显示时可能暂时位于零坐标，并重建鼠标 tracking area。未定位的 frame 不得参与窗口尺寸预算；Enter 事件必须核对当前鼠标命中，不能单凭回调自动展开。`pet_surface_qa --smoke` 的关→悬浮→停靠回归用于发现“刚收起又自动打开”。


## 原生尺寸与共享元素动效

展开/收起涉及 native frame 重定位时，以屏幕坐标验证共享元素，不只比较 DOM 局部坐标。扩大原生窗口前保留旧视觉位置，收起动效结束后再缩小原生窗口；测量阶段暂停观察器的重复写入，结束后恢复。标题、头像只平移，不随背景比例缩放。目标列表的响应式布局依赖目标容器宽度，不能依赖尚未调整的旧 WebView viewport。

动画验收必须包含连续帧：居中、边缘限位、反向中断、最后的 native 收缩，以及减少动态效果。截图与 rAF/native IPC 不一定同帧，必须保留采样时序或在截图中编码当帧尺寸，防止把采样错位误判为窗口跳动。背景之外的透明区域不参与命中。来源与验证脚本见[共享内容展开动效](../30-domains/pet-window/top-edge-docking.md)。

准备共享元素动画时不能用 `visibility:hidden` 隐藏焦点所在容器；这会让 focusout/leave 改变状态机并触发自动收起。视觉快照遮盖期间保留真实内容的焦点与命中，动画结束后恢复；键盘展开后应继续聚焦顶栏，Escape 保持收起直到重新进入。


浏览器截图、WebView rAF 和 AppKit frame 采样均不能单独证明原生合成无闪烁。涉及 native resize 的动效，必须连续捕获真实 macOS 窗口像素，包含扩容前后、收缩末帧和反向。截图工具若在点击完成后才返回，不能据此声称覆盖了动画起点；使用隔离 native fixture 自主触发动画，CUA 同步连续读屏。保留失败基线以验证检测器确实能发现空白/裁切/偏移。不要在同一共享元素动效混用 compositor transform 和 layout 宽高时钟；图像快照只用于尺寸交接，不能长期替代可交互 WebView。参见 [原生动效排查](../40-runbooks/pet-native-motion-flicker.md)。

动画只能延迟视觉状态，不能延迟回写整个交互状态机快照；hover、focus、Escape 和拖动输入必须立即生效，否则排队动画会覆盖后续输入并把刚收起的面板重新打开。`DockPanel` 的状态机保持最新输入，私有动效驱动只维护呈现进度。用后台 hover → focus → Escape → 保持鼠标不动的完整 UI 回归验证。

顶部动效只能访问组件拥有的容器，禁止查询任务标题/Provider 等业务后代或克隆业务 DOM；正文与顶栏节点在展开收起之间保持挂载，关闭正文退出键盘和鼠标交互。内容尺寸变化合并测量，不能逐帧写原生窗口；真实指针移动与几何变化合成的 enter/leave 要分开，避免收缩后重新打开。任务 UI 变更运行 `npm run test:pet`、`npm run test:pet:ui`、`npm run test:pet:motion`，来源及取舍见[顶部动效组件边界](../10-architecture/dock-panel-motion-boundary.md)。
