# Codex 工作台只读快照与状态边界

## 规则

工作台只读扫描本地会话和 Git；操作必须通过当前 scan ID、工作树 ID 和文件/对话 ID 查找目标，不能接受前端任意路径。Git 变化属于工作树，不属于共享它的某一条对话。

## 适用场景

历史检查的扫描、单树重检、文件预览、目录定位和 Codex 深链；前端总览、状态筛选和详情。

## 反例

旧重检响应覆盖新扫描；无上游的干净工作树显示为已推送；筛选“未推送”后总览工作树数量也随状态条件变化；将一个共享工作树的文件修改归入一条会话；以普通空格拆分 Git 路径或遗漏 unmerged 的 hash 字段。

## 推荐做法

使用扫描 generation 隔离旧任务。系统动作在桌面适配层查找快照中的目标并复核路径；平台动作留在统一接口后。Git 使用 NUL 分隔，只依赖本地 remote tracking refs，设置禁锁、禁 lazy fetch、禁 fsmonitor，不主动 fetch。冲突/普通/改名记录分别按 11/9/10 个字段解析。改名记录消费后续原路径。汇总在项目、关键词、日期和关联对话基础条件上计算，提交状态只进一步过滤列表。

预览限制 UTF-8、256 KiB 和工作树内路径，HEAD 使用扫描时记录的 revision；版本读取返回后检查响应序号，关闭时销毁编辑器。

工作台及其 dialog 必须继承 App 主题。颜色别名放在 `frontend/lib/theme/main-window.css` 的 `.main-theme` 上，引用现有语义 token；不得在组件内固定 `color-scheme: dark` 或重写 `--app-*`。详情按需打开右侧抽屉，列表不保留空白栏；复用共享弹窗栈，让 Esc 先关闭预览再关闭抽屉，并恢复到各自入口。抽屉定位样式须高于共享居中弹窗默认样式，须在完整 App 壳中验证。编辑器差异和折叠区域同样随主题变化；用打开预览时切换主题的 UI QA 验证，保持编辑器身份、结果和布局不变。

来源后备策略必须依据本次源读取是否成功决定，不能依据循环中不断增长的结果集：数据库不可读时应扫描全部后备会话头；数据库可读时只修复标题索引中缺失的 ID。本阶段仅扫描 Codex，不读取其他 Agent 的历史目录。配置了上游但不存在可比较的本地引用时，不能显示“已同步”。

无关联会话不代表工作树无改动；默认检查范围包含这些目录，失败目录提供可直接进入的筛选。对话条数、文件条目数和 ahead 提交数须分清单位，不用这些事实推断任务完成度。
