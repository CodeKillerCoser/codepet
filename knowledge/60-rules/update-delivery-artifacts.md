# 更新交付与发布产物一致性

## 规则

修改发布平台、架构或安装包格式时，必须同步检查客户端更新策略。仅实际提供可安装的 updater 产物时才走自动安装；手动安装包必须明确标示交付方式。

## 适用场景

Release 工作流、清单生成、平台更新接口和更新弹窗变更。

## 反例

发布流程删除 Mac universal updater 归档，仅上传 ARM64 DMG，客户端仍请求 `macos-universal`。即使版本已经最新，也可能因缺少平台条目而报错。把 DMG URL 填入该条目不能修复格式不兼容。

## 推荐做法

平台层根据实际发布策略返回更新能力；业务和 UI 按能力操作，不散落系统判断。匹配版本、架构、上传状态和非空产物；缺包或网络错误明确报告，保留重试。同一基础版本的构建后缀变化不强制升级。

安装包名称必须包含平台、架构、基础版本和短 commit；改名时同步维护客户端识别和 updater URL，并保持签名字节不变。Build 固定完整 commit 并保存产物，Release 只发布指定成功运行的原产物，不重新编译或覆盖其版本身份。固定入口 `latest.json` 保持原名。

## 来源

[Mac 检查更新目标缺失](../40-runbooks/macos-update-target-missing.md)。

## 验证方式

覆盖旧版本到新版本、同版本、缺少目标产物、架构不匹配和失败重试。发布后请求真实更新入口并检查产物链接；自动安装与手动下载分别验证 UI。原生安装未执行时明确记录验证缺口。
