# 源码文件长度与拆分

## 规则

手写源码单文件以 1500 行为拆分审查点、2000 行为硬上限。超限按职责、数据所有权和测试边界拆分；禁止压缩排版、删除必要注释或机械编号分片来满足行数。

## 适用场景

Svelte、TypeScript、CSS、Rust、Node 脚本、Python 与 Objective-C 源码及测试。生成的协议类型、打包后的独立 Provider 示例和 vendor 不手动拆分，应改生成器或模块源文件。

本轮已使前端全部源码低于 1500 行。现存后端/工具长文件列于 [UI 重构记录](../10-architecture/svelte-ui-component-refactor.md)，本轮仅审查、未改业务。后续修改这些文件时应完成职责拆分；不能因为是既存文件就继续增加超限内容。

## 反例

把 App 的状态和所有页面放入一个组件，或把 3000 行 CSS 保留在一个全局文件；把 Rust 方法按行数平分为 `part1/part2`，仍然共用隐式全局状态。

## 推荐做法

- App 保留应用壳层和跨页面装配，设置页管理自己的交互生命周期，持久化保持明确的回调接口。
- CSS 按基础、主界面、设置、桌宠和响应式拆分，入口显式保留原有级联顺序。
- Rust 按实例生命周期、协议映射、目录/分页、事件和存储等职责拆；保留公开 re-export 和附近合同测试。
- 1501–2000 行允许在审查后维持，但应说明独立职责与后续增长边界；超过 2000 行的受检文件必须拆分。

## 来源

2026-11-24 用户明确要求整体 UI 重构及 1500–2000 行的文件长度约束。

## 验证方式

`npm run check:source-size` 检查整个前端和本次修改/新增的其他源码；`node scripts/check_source_size.mjs --review` 额外展示全仓历史长文件。CI 通过 base SHA 检查已提交的变更，避免只检查工作区 diff。专用 workflow 不需要安装依赖。通过尺寸检查不代表模块边界合理，仍需审阅职责、共享状态和附近测试。
