# 桌面状态存储规约

## 规则

用户配置以 JSON 文件为唯一来源；会话和 Provider 业务记录以结构化 SQLite 为唯一来源。标量映射列，一对多关系映射关联表，不将完整对象、请求或响应序列化成数据库 JSON 文档。

## 适用场景

Host 身份、实例、连接凭据、会话活动/已读、Host 输入队列和 Provider 用量。手机存储、任务抽取与谱系不在本轮范围。协议传输使用 JSON 不受本规则限制。

## 反例

SQLite 的一行保存整个 conversation_state JSON，两个进程各自读改写会丢更新；每次更新会话活动顺便覆盖队列列，会丢失另一条业务路径的控制状态。把未知 token 保存为 0 会伪造统计完整性；对完整正文做哈希会让流式更新成本随历史增长。

## 推荐做法

- 共享身份和会话关系使用 app-state.sqlite，插件用量使用各自的 usage.sqlite；路径由 Host 注入。
- 输入队列用字段及关联表保存正文、配置、认领和操作记录，先落盘后派发。请求重试逐字段比较，不哈希正文；结果未知暂停，不能凭请求 ID 盲目重发。
- 活动计数、观察值与已读更新使用同一事务入口，只更新实际变化的字段；队列版本与活动版本分开。
- 会话摘要先截取至多 512 个 UTF-8 字节的完整字符前缀，再 trim 和哈希；详情只哈希有界 ID，事件键直接保存。禁止哈希正文、历史集合、工具输出或完整排队请求。
- 用量保留 NULL、known_count 和完整性；快照绑定与结果拆成字段及有序子表，事务读取。
- 损坏的共享库报错，不因一个身份/凭据对象异常删除整库。新格式不读取旧文件是 2026-11-08 用户授权的本次边界，不代表以后可以自动丢弃用户数据。

## 验证方式

运行 Provider 数据层测试和 Host 单线程回归；重点覆盖 `tests/storage_schema.rs` 的并发、外键回滚、读者隔离及 queue 字段保留，`tests/usage.rs` 的冻结查询和 NULL 语义，以及 Host 的设备、配对和 Gateway 测试。发布前验证真实手机重新连接和安装包路径。
