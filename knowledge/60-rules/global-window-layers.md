# 全局窗口层级与焦点

## 规则

模态弹窗和模态抽屉统一通过 `frontend/lib/ui/dialog` 挂载与登记；最近打开的窗口及其遮罩必须位于此前窗口之上，内容又必须高于自己的遮罩。标题、关闭动作与正文各有明确边界；侧栏正文由框架用统一圆角卡片包裹。

## 适用场景

App 第三栏、窄屏抽屉、文件预览、任务表单、配对和更新窗口，以及从已有窗口再打开新窗口的流程。

## 反例

不同弹窗固定共用同一 z-index，导致后挂载的抽屉覆盖先声明的预览；把弹窗留在具有 transform、contain 或裁切的业务容器中；原生 dialog 的 top layer 与普通 DOM 弹窗混用；只验证编辑器存在而不检测按钮实际命中；在窗口刚出现时截取动画中间帧并当作最终布局。

## 推荐做法

使用共享 Dialog 的默认 portal，将窗口移到主题根内唯一的 `.app-window-host`。窗口栈按打开顺序分配遮罩与内容的相邻层级，退出动效中的旧窗口不能覆盖新窗口。业务页不要自行提高 z-index 或增加备用 host；需要原生式调用入口时使用 `Dialog.Modal`，并保留表单忙碌时的取消拦截。

框架统一承担标题、关闭按钮、圆角正文、进退动画、断点、遮罩和焦点生命周期；标题必须由使用方填入。关闭最上层窗口先返回其触发元素，再允许关闭底层抽屉；WebKit 的鼠标按钮点击可能不改变 activeElement，不能仅依赖它推断触发元素。关闭动效期间禁用正文交互，并尊重减少动态效果。

弹窗移出业务容器后，检查主题继承和原有 container query 是否仍适用。最终截图等待动效结束；另行采样连续帧验证展开和收起，不以固定延时替代状态与动画完成条件。

从菜单打开弹窗且菜单随后关闭时，不能把隐藏菜单项作为返回焦点。调用方通过 `Dialog.Modal` 的 `returnFocus` 指定仍可见的菜单触发元素；仅检查 `isConnected` 不足以证明元素可聚焦。任务页接入弹窗须验证点击打开、Escape 关闭后返回“更多任务操作”，并能立即用键盘重新打开菜单。

## 来源

## 验证方式

运行 `windowStack.test.ts`、`sidePanel.test.ts`、工作台 Chromium/WebKit QA 和共享 UI QA。验证文件预览的 elementFromPoint 点击命中、实际版本切换、焦点及 Escape 顺序；任务表单额外运行 `scripts/task_ledger_ui_qa.mjs` 检查忙碌取消拦截。新增窗口时同时验证浅暗主题、窄屏、快速重新打开和退出动画期间的新窗口。
