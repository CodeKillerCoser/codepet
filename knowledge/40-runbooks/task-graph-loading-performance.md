# 图谱加载性能排查与按需语义预览

## 现象

用户报告任务图谱打开极慢。普通 Graph 的请求必须等完整 Semantic 预览生成，页面在响应前只能显示“正在读取真实任务图谱”。

## 证据

2026-11-26，macOS arm64。当前用户活动索引为空，直接 `/graph` 约 2 毫秒；这只能证明空态链路可用。性能基线使用既有隔离加工数据的副本，152 节点、347 边；模型端点指定不可用 loopback，不执行模型抽取，不修改用户模型配置或正式索引。

- 基础图首次导出：1.0254 秒。
- Semantic 首次导出：37.1172 秒；同进程后续为 0.0668、0.0630 秒。
- 浏览器直接挂载完整快照：232.5 毫秒，后续 48.5、44.9 毫秒。
- 新进程读取持久缓存：基础图 1.7 毫秒、语义图 2.3 毫秒；按需版本浏览器测得 195.9–352.4 毫秒。浏览器负载与运行顺序不同，不将渲染样本声称为严格同条件加速倍数。

原始日志在 `artifacts/graph-performance/backend-before.json`、`backend-restart.log`；真实快照来自 c0ca 工作区既有 preview-graph.json。首次语义耗时包含依赖与原生投影的冷启动，本轮未将其再细分为 JIT、向量读取和聚类各自耗时。

## 根因与引入历史

`Recall::graph` 始终传 semantic=true，`Engine.graph` 依次执行基础图和 `visualize_semantic_json`，没有预览结果缓存。前端因此在普通 Graph 阶段承担不需要的语义等待。Cognee 自身预热后较快，不能据热请求结果否定首次打开的实际延迟。

相关实现来自 fc159952；未确认该提交前其他实验入口是否存在同样问题。

## 修复与涉及模块

- Host/Rust：API 41 增加可选 semantic 请求；老调用省略字段仍使用完整语义图。前端初次明确请求 false。
- Python Engine/GraphCache：基础图和语义图分别缓存，配置及 dataset 隔离；原子写入、大小上限和版本校验。所有原生写入前后失效，预览与写入串行，失败后不复用旧图。缓存是可丢弃派生数据，不能改任务/执行状态。
- cogneeGraph/iframe bridge：Semantic 首次切换才请求，重复点击共享一次请求；失败可再次点击重试。保持原生节点、坐标、簇、视图与资源，检查快照版本防止跨代应用。
- frame 集成层：只对全部固定的 Story 坐标提前绘制并解除遮罩；不重写上游布局算法，不改 vendor 哈希。

## 验证与回归防线

Python 26 项测试通过，覆盖并发只导出一次、重启免加载原生模块、profile/dataset 隔离、缓存损坏、语义失败重试和索引部分写入失败后的失效。Node 5 项覆盖资源原始哈希、脚本转义、私有上游变量隔离和受限消息。相关前端组件与请求测试通过；Rust MCP 单测以及 Tauri cargo check 通过。前端检查保留 5 项既有警告，API 41 前端构建及 source-size 检查通过。

Ego 浏览器使用真实快照检查 Graph/Schema/Memory/Semantic、按需请求、失败重试、错误 token 不触发请求、主题及截图。截图不冒充实际 App WebView 验收。

复测：同一索引先请求 semantic=false，再单独请求 true，各连续两次；重启进程后重复并比较 native 导出调用次数。修改/删除一份索引文档后，确认新 previewVersion 与新内容；校验读取预览不增加模型用量。大图另测节点规模、首次原生布局和 IPC 字节量。

## 未知项

未替换本机 App，尚未验证 API 41 原生安装包、Windows 和更大图谱。升级必须同时包含 Rust、Python sidecar 与前端；旧服务复用的升级问题需独立处理，不能通过删用户账本或伪造空图规避。

## 函数级加速与大图压力测试（续测）

用户补充实际规模约 700 节点、1,600 边，要求先优化计算函数。`codepet_recall/semantic_layout.py` 现用二维空间网格筛选距离小于 min_dist 的候选对，保持原生 RNG 消耗、40 轮、推开公式和对称位移。稀疏邻域只算必要点对；密集桶或候选数量过多时回到原有 NumPy 全量向量化步骤，避免重合点退化成大量 Python 双重循环。仅在需要语义计算且缓存未命中时挂接 `_deoverlap`，PCA、聚类、向量读取和采样上限不变；框架函数签名变化必须复核。

正式函数的单次对照：700 个二维点去重叠 359 → 72 毫秒；2,000 点 2,822 → 264 毫秒。700 节点、1,600 边、1,024 维合成向量的完整坐标/聚类/邻居计算 482 → 184 毫秒；真实 152 节点快照经生产 Engine 调用确认新函数已接入，坐标最大差为零、聚类完全一致。随机与边界样本的最大浮点差约 1.5e-15，按 1e-11 容差验证；重复运行仍确定，输入数据和 RNG 后续状态均保留。交替计算顺序的3次基准，中位数为700节点完整计算446→184ms（2.42倍），2,000节点3.480→0.939s（3.70倍）；坐标最大差分别为0和1.15e-15。补充后 Python 共 30 项通过。可重复基准为 `scripts/semantic_layout_benchmark.py --bundle <解包目录>`，结果取交替顺序多次计算的中位数；输出在 computation-benchmark.json。

分阶段 profile 进一步说明：152 节点的独立进程中，导入可视化模块约 1.86 秒，首次存储向量读取约 2.75 秒，PCA 约 5.9 毫秒、去重叠 16.9 毫秒、聚类及邻居合计约 9.7 毫秒。该次请求约 2.99 秒，后续约 0.22 秒；OS/依赖已预热程度不同，不能把先前 37 秒全部归因于数学或 Python 循环。2,000 个 1,024 维合成向量中，原生完整计算约 3.54 秒，去重叠占约 2.87 秒，PCA 约 0.18 秒，聚类/邻居约 0.47 秒，故先改空间筛选而非迁移 Rust 或 GPU。

压力工具 `node scripts/graph_performance_probe.mjs` 仅绑定 loopback，生成规范 stage 字段的合成图，不读写账本。浏览器直接加载结果：

| 节点 / 边 | JSON 字节 | 读取、解析及挂载合计 | 单次 Canvas 重绘 CPU |
| --- | ---: | ---: | ---: |
| 700 / 1,600 | 362,639 | 0.192 秒 | 0.1–0.5 毫秒 |
| 20,000 / 60,000 | 11,999,228 | 0.512 秒 | 2.2 毫秒 |
| 50,000 / 150,000 | 30,168,228 | 1.219 秒 | 5.4–5.7 毫秒 |
| 100,000 / 300,000 | 60,508,228 | 2.477 秒 | 22.6–74.1 毫秒 |

这些是合成数据和浏览器直接传输，**不包含真实索引导出及 Tauri IPC**。100,000 节点样本超过当前 Rust 32 MiB 响应上限，不能宣称产品链路支持。此规模还出现 42–250 毫秒的消息往返与重绘响应，点/边视觉严重堆叠，不应以“ready”代替流畅/可读验收。浏览器自动化环境的 rAF 出现约 1 秒调度间隔，不使用其 FPS 作为产品帧率结论；CPU 重绘耗时与 ready 回执单独记录。完整回执和截图在 stress-results.json、stress-100000.png。

函数优化阶段没有迁移计算时机。2026-11-27 已进一步在有效加工完成后发布基础图快照，并让页面按版本自动读取，见 [边加工边预览](task-graph-progressive-preview.md)。首次 Semantic 仍按需准备，不能用基础图预生成或算法提速冒充所有语义冷启动等待已经消失；原生安装包升级的验收仍单独进行。
