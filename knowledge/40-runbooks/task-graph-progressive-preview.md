# 图谱加工期间无法浏览与自动刷新

## 现象与证据

用户要求第一份结果出现后即可浏览，并在后续加工中自动更新。`Service.worker` 持有 `busy` 直到单次模型加工结束；旧 `/graph` 必须竞争同一锁。队列连续运行时，即使已有完成记录，预览仍返回 409。Engine 写入前后清除工作缓存，单纯去掉服务锁还会读到写入中的原生索引。

隔离 HTTP 回归阻塞第二个加工协程，确认第一个已完成结果可读；随后释放协程，图谱版本与节点更新。既有真实索引副本的 152 节点、347 边在模拟写锁持有期间约 0.25ms 返回，knownVersion 响应仅 157 字节。该数值来自已缓存数据，不是冷启动原生导出或真实模型加工测速。

## 根因与引入历史

预览读取与长期写任务只有互斥，没有独立的已完成结果发布边界；页面也没有持续检查首份结果。具体引入提交未确认。

## 修复与模块

- Python `PublishedPreview` 独立持久化最近成功预览，继承 GraphCache 原子替换及私有权限；按 fingerprint/dataset 校验。Catalog 只对有效完成返回发布许可，失败与被更新覆盖的尝试不发布。工作缓存的原有失效规则保留，禁止在写锁下重新读取原生数据库。
- Service 在完成时发布基础图；页面繁忙时直接读取已发布结果。首次升级尝试在下一次写入前导出已有索引；没有结果则返回 409。语义投影失败不重复模型加工，同版本语义结果才可复用；首次请求仍可能等待原生准备。
- Rust 透传可选 knownVersion，保留旧完整响应兼容。相同版本返回小型 unchanged/previewStatus，避免每 5 秒传输完整图。
- TaskKnowledgePage 单次请求串行轮询，隐藏时暂停、回到前台补读、卸载后清理。新图就绪前保留旧图；无版本变化不重绘。沙箱薄桥保存视图、搜索词、主题和 Graph 视口，交互时推迟后台替换，不改 vendor。

## 验证与复测

Python 全套 37 项、前端页面及请求 10 项、沙箱桥接 4 项通过；Rust MCP 18 项通过（4 项显式集成测试忽略），Tauri lib 编译通过。前端检查 0 错误、5 项既有警告，生产构建、源码尺寸与 diff 检查通过。普通 python3 缺少 numpy/httpx；全套使用已安装 sidecar 的 runtime 与 packages，CI 的生命周期子集仅依赖标准库。

Ego 浏览器使用模拟 IPC 和真实索引快照验证首次 409 后自动出现、队列未完成时持续展示、新版本保留 Schema、同版本 iframe 身份不变。截图与离线探针在 `artifacts/graph-performance/progressive-native/`；测试没有写生产索引、调用模型或重启正在加工的进程。

复测先保持至少两项队列，等待首项完成但下一项仍 processing；打开工作记忆应有图，后续 5 秒内检测新版本。拖动或切换视图时不得被后台强制重置；离开页面不再继续请求。Semantic 忙碌需显示准备并重试，不能错用旧坐标。磁盘快照损坏应回退，不把预览误用于召回有效性判断。

## 回归防线与未知项

约束沉淀到 [本机任务边界](../60-rules/local-task-mcp-transport.md)，Linux/Windows 生命周期 CI 纳入发布快照测试。本机仍是 API 40 的安装版，当前修复需要新的 Rust/sidecar/前端安装包，浏览器 QA 不冒充原生验收。Windows 实机和 Schema/Memory 独立平移缩放恢复尚未验证；当前只保留所选视图，不恢复这两个视图的独立视口。
