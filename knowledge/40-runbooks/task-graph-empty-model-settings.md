# 图谱为空时错误提示配置模型

## 现象与证据

2026-11-27 用户已保存本地模型，图谱页仍要求配置。首次只读检查 managed 安装记录指向的活动数据目录：语言模型、向量模型和 1024 维均已保存，但 `model-gateway/config.json` 的 `enabled=false`。首次诊断未读出密钥、未修改配置或触发模型调用。

`TaskKnowledgePage.svelte` 原先只根据 `nodes.length === 0` 展示“配置模型”，没有读取模型设置。同样的提示也会出现在模型已启用、尚无加工结果的情况下。原单测反而将这个错误映射固定为预期。

## 根因与引入历史

把“索引没有节点”当成“模型没有配置”。模型配置是否完整、加工开关是否开启、是否存在加工结果是独立事实。引入提交未确认。

## 修复方案与涉及模块

- `TaskKnowledgePage.svelte`：仅在空图时通过既有 `model-settings` IPC 读取保存状态；缺少模型引导配置，已配置未启用提示打开加工开关，已启用无结果提供刷新与加工历史说明。读取失败展示真实错误，不猜测缺少模型；刷新重新读取，卸载后丢弃回执。
- `TaskKnowledgePage.test.ts`：分别覆盖三个空态、配置读取失败、刷新更新状态，以及原有视图保留、退出清理。显式确认组件只读配置，不自动开启加工。
- `frontend/qa/main-window.ts`：新增关闭加工、缺少模型和配置读取失败的独立模拟场景，生产打包不包含此入口。

## 验证结果

图谱和模型设置相关 12 项测试通过，`check:frontend` 无错误，生产构建、源码大小和 diff 检查通过。Ego Browser 在模拟 IPC 页面核对三个空态及读取错误，模型设置入口保留两种模型并显示关闭的开关；浅色正常尺寸和 780×680 暗色截图已目视检查，无水平溢出。截图位于忽略目录 `artifacts/graph-performance/models-disabled*.png`。这些浏览器样例不代表正式加工验收。

## 回归防线与限制

空图不能作为模型配置检测方式；配置读取失败也不能降级为“未配置”。空态组件沿用已有 IPC 与主题，无新增原生接口，不修改模型设置或自动开启加工。本机安装版本 `f0b04cd` 是 API 40，当前完整 WebContent 为 API 41，不能仅替换前端冒充升级后端。

## 后续实际 App 自动与主动加工验证

用户明确选择：必须先打开总开关，所有符合条件的执行自动加工，主动操作不能绕过开关。正式数据按 `projects.json` 注册项目读取，实际为 9 Task、15 Run（14 个已结束、1 个开发中）；不能把 maintenance 备份算进任务数。旧 Catalog 只有待加工记录，没有已完成索引，也没有主动操作回执。本机两种已保存模型均可从本地服务列表读到。

在实际 App 点击任务的 Sparkles 图标，先复现关闭开关时的拦截。按用户选择在原生模型设置页开启并保存，再点击图标，发现另一个阻碍：旧 stdio runner 持有的 sidecar fingerprint 仍对应 `enabled=false`，App 请求持续返回“任务召回正在切换模型配置”。核实该进程的解释器路径、父进程、健康指纹，以及 `processing=0` 后，仅终止这一空闲旧 sidecar；未终止父 MCP 会话、未清理任务、队列或索引。App 随后以新配置接管，正式历史显示 1 processing、13 queued，首项已有实际模型 Token 记录。再次从任务详情点击主动加工，返回 existing=1；SQLite `manual_requests` 新增一条回执，没有重复加工项。

这是正式 App 的实际链路验证，不是 fixture。总开关保持开启，后台继续处理其余执行；入队和模型请求已验证，不把尚未完成的全量索引记作全部成功。此前 stdio 工具的格式版本错误仍存在，但 App HTTP MCP 可以读取和更新同一任务记录，后续回执改走该真实协议入口。

主动加工的后端拦截文案改为准确的“启用任务语义与图加工”开关名称，并补充断言，避免将未启用说成未配置。
