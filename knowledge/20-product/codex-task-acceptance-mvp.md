# Codex 主动登记任务的本地 MCP 最小方案

> 2026-11-24 首版已实现。只接 Codex；接入配置与验收命令见 [本地 MCP 接入与验收](../40-runbooks/codepet-task-mcp.md)，领域定义见 [Task 与处理轮次](../30-domains/task-management/task-record-model.md)。

## 背景

Git 工作台解决工作树残留，任务账本解决一个对话包含多个目标、同一问题跨对话反复修复后难以找回方案和验收依据。用户要求维护任务不能给开发中的 Codex 增加重负担，MCP 必须独立在 Rust 层运行。

## 目标

Codex 在关键节点自主登记任务、方案、验收点和进展；App 展示同一本地账本，支持人工验收、结束与复发重开。旧轮次和旧验收结果保留。无需每次登记让用户确认。

## 非目标

不扫描全量对话、不另起摘要模型、不自动执行测试、不同步云端、不推断文件/分支上全部提交属于某个任务。首版不做旧 v1 迁移、验收豁免、历史记录更正界面、结构化 SHA 替代关系或证据附件上传。

## 现状理解

旧任务抽取以 root thread 为范围，不能直接沿用其 Task。`codepet-task-lineage/src/tasks/` 新建独立 schema v2 领域，复用 Store 的原子事务、锁和恢复机制。工作树 Git 状态继续属于共享工作区，不能冒充任务归属。

## 实现路径

### Rust 独立入口与共享账本

`codepet-task-mcp` 使用官方 Rust SDK rmcp 的 Streamable HTTP。App 启动时由 Rust 后台在 `127.0.0.1:47623/mcp` 提供服务，主窗口只展示可复制的 URL/凭据配置。Codex → 本机 HTTP MCP → Rust Ledger → 本地 JSON；前端没有请求转发、服务生命周期或模型上下文维护责任。关闭界面而 App 仍运行时服务保持，退出时统一取消并释放监听。旧 stdio/`--task-mcp` 只作为兼容入口保留。

人工 IPC 与 HTTP 使用 App 托管的同一个活动 Ledger，数据目录切换在重启后生效，避免同一 App 内两个入口写到不同账本。未就绪或端口占用时不生成可用配置；凭据、Host/Origin 及回环监听边界在 Rust 校验。传输改动不增加工具或日常维护调用。资源 API 升至 27，避免 API 26 的旧二进制误展示 HTTP 配置。

桌面经 `task_ledger_request` 直接调用相同 Ledger，Actor 固定为 human；MCP Actor 固定为 agent，工具参数不能覆盖。账本在应用 data/tasks/v2；自定义数据目录沿用 bootstrap settings，关闭窗口而 App 仍运行时可写；退出 App 后 HTTP 服务停止。

### 两个工具与两次常规写入

| 工具 | 用途 |
| --- | --- |
| tasks_find | 恢复旧任务时搜索简短列表，或按 ID 读取当前轮与清单；历史摘要须显式请求 |
| tasks_save | 一次保存目标、方案/清单、进展、自测、明确关联提交、交付引用；也可用 reopenReason 新开一轮 |

开发阶段通常只在方案确定/开始实施与实现或自测告一段落时各保存一次；实际发布时再保存一次已发布与版本引用。切换独立任务、方案明显变化、复发时才额外补记。保留返回 taskId/revision，更新省略不变字段，不在每条消息、每个文件或每次工具调用后写入，不轮询。AGENTS 简短规约放在 `crates/codepet-task-mcp/instructions.md`，App 提供复制入口；MCP 初始化也携带相同原则。

服务生成 UUID、轮次、修订、时间、验收项 ID 与事件，读取分支、HEAD、dirty 及显式关联 SHA 的本地缓存上游可达性。普通保存只返回回执。真实 HTTP 和 stdio 验收会记录工具定义与回执字节数，并用预算测试避免无意扩大工具面，避免让历史账本进入日常上下文。

### 并发、重试与来源

更新要求 expectedRevision，冲突不覆盖人工修改。operationId 可省略，服务用请求指纹生成幂等键；显式键复用但参数不同会报错。回执和任务在同一事务提交，重启后可重试。App 失败重试保留同一操作键。

项目 UUID 由服务持久化映射到规范化 Git common directory，同仓库多个 worktree 共用项目；非 Git 目录按规范路径映射。目录移动/重新克隆的自动映射尚未实现。对话 ID 不从模型猜造，也不假定 MCP 自动传递 thread ID；显式提供时只查本地 Codex SQLite 的一条 cwd 并核对仓库，来源不可读则待核实，已知跨项目来源拒绝关联。

### 验收与历史

主状态仅为进行中 → 待交付 → 已发布 → 已结束。排查、方案、开发、本地测试写进展，不维护额外流程状态。MCP 完成实现时设 ready_for_delivery，实际发布时设 published 并同次提供 delivery；不能根据提交/推送推断发布。验收失败回到进行中，但旧发布与验收记录保留。人工结束只选择是否验收通过并填写可选说明，不再展开取消、替代、排查结束等结果菜单。类型也不出现在主要界面与编辑表单。

清单追加修订，验收记录绑定计划版本、阶段、实际目标、环境、执行者和逐项证据；本地与发布后分开。人工“验收通过”检查当前清单必验项的人工结果，同阶段不能从不同目标/环境拼出通过。取消/被替代/排查结束不伪造通过。

复发追加 Round，服务自动复制旧清单并生成新项 ID，结果为空；新方案可同时覆盖为新的清单。旧轮保持原结果。当前首版代码关联保存 SHA 与观测，最终集成、构建与发布可通过交付引用登记，尚无结构化 SHA 等价证明。

### 展示

沿用 Agent工作台导航和主题，通过“代码状态 / 任务与验收”切换，不增加大标题。任务页提供项目/状态/文本过滤、轮次选择、方案清单、代码观测、验收记录、来源与时间线；窄窗口为列表与详情切换。前端手动操作通过桌面 Rust 适配器落库；聚合和状态校验始终在 Rust。待交付时展示服务端生成的 Git 明细：共享工作树待提交、关联提交待推送/已推送，或待确认；这些是带观测依据的说明，不增加主状态或 Agent 维护项。

2026-11-24 界面层级调整：保持左列表、右详情与原导航。列表去掉重复目标正文，约 90px 一行；右侧按目标、当前阶段、本地/发布验证进度、方案与验收点排列。验收点改为无卡片背景的行，优先展开失败项，无失败时展开第一项。代码/路径、背景、验收记录、对话与时间线默认折叠并保留摘要。以字号、字重、间距和细分隔组织信息。状态仅在小标签上使用主题浅色底：进行中浅蓝、待交付浅琥珀、已发布浅绿、已结束浅灰；浅/暗模式自动继承语义 token，保留状态文字。

2026-11-24 按后续标注收紧：二级导航由 App 的 `AppContentPane` 可选插槽承载，放在 `.content` 滚动区域之外；工作台与连接接入共用位置，不需要导航的页面不占位。任务搜索、项目与状态筛选移入顶部工具栏；移除重复任务统计标题、详情项目名以及列表/详情顶部的交付提示，Git 明细保留在“代码与交付”内。“接入 Codex”移入更多菜单。列表使用“N 次处理”；只有多次处理才显示历史选择，旧处理保持只读。此次不改变 Task/Round、存储或 MCP 协议；用户提出的“任务 / 任务执行”职责划分留待单独讨论。

## 涉及模块

- `crates/codepet-task-lineage/src/tasks/`：新领域、项目身份、轮次、清单、验收、来源核实和紧凑投影。
- `crates/codepet-task-lineage/src/store.rs`：共享存储；补显式释放锁，防止复制描述符延长操作生命周期。
- `crates/codepet-task-mcp/`：两个工具、本机 HTTP、stdio 兼容、开发规约和独立进程入口。
- `src-tauri/src/task_ledger.rs`、`app/cli.rs`、`lib.rs`：桌面人工入口及打包内 MCP 入口，主窗口限制。
- `frontend/lib/TaskLedger.svelte`、`taskLedger.ts`、`CodexWorkbench.svelte`：展示和人工操作，复用主题。
- `webcontent-contract.json`：新增原生命令，backend API 升至 26，旧安装版需升级原生程序。

## 风险

主动登记遗漏：只约定关键节点，保留手工补录，不承诺模型永不漏记。工作区事实误归属：明确共享工作树与显式提交的区别，带观测时间。覆盖与重复：修订检查、幂等事务及并发测试。不同版本混验：按计划版本、目标和环境隔离，复发不继承结果。来源误绑：单条本地索引核实，缺失保持待关联。布局/焦点：原生交互验收与多尺寸浏览器验证。信息过度折叠：检查失败验收项默认展开、折叠摘要可识别及键盘展开。阶段进度误拼版本：沿用 latestResult，按本地/发布分别统计最新目标结果。

## 测试计划与结果

已执行共享领域/存储测试、真实 HTTP/stdio 无前端验收、官方 SDK HTTP 客户端、桌面二进制 HTTP/stdio 入口、原生 Tauri IPC 的人工验收/关闭/重开/历史与冲突草稿验证、主题和响应式布局。具体命令、证据目录及环境限制见接入 runbook；测试任务与验收文本是临时样例，不代表样例描述的业务问题真实发布过。
