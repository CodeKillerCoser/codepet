# 全局 UI 视觉基础评审与行业参考

日期：2026-09-08。状态：历史评审依据。后续用户已确认共享壳层背景、大圆角内容面板、紧凑品牌区及平台窗口控制；最终以 [更新后的设计规范](ui-foundations-proposal.md) 及其正式视觉稿为准。下文保留原评审证据，不作为与最终规范并列的约束。尚未应用到生产界面。

## 背景与目标

评审 [UI 视觉基础提案](ui-foundations-proposal.md) 和 [视觉板](../../design/ui-foundations/visual-board.png)，判断其视觉与交互规范是否足够进入实现，并寻找可借鉴的成熟产品设计。结论：保留暖中性色、平铺内容和全高分栏；下一步重点是信息权重、操作含义和状态覆盖。

- 已完整阅读提案，并直接查看视觉板。视觉板为生成式概念图，精确字号、颜色和业务文案不能据此反推。
- [产品意图](../00-project/product-intent.md)将主窗口定位为配置和数据查看，桌宠负责后台任务感知。因此本次不建议把主窗口改成新的任务工作台。
- 提案已有语义 token、焦点、对比度和浮层规则；不能把“图上未展示”写成“规范没有”。

## 现状理解与评审发现

### 1. 顶部摘要的视觉权重缺少区分

证据：主窗口顶部将 Hooks 数量、最新状态和授权提醒排成三块等权摘要，大字展示“0”“待命”“响铃”，下面又出现端点地址。

判断：数量、活动状态、通知偏好属于不同语义；等权展示让用户难以判断哪个需要处理。概念图文案可能失真，此处指出的是层级风险，不认定业务标签错误。

建议：沿用现有内容，压缩摘要高度；当前接入状态优先，提醒偏好次级，地址采用代码文字与明确查看入口。不要把静态偏好排成重要指标。

验证：使用真实字段分别排出全部未接入、正常接入、接入异常三种场景，检查第一眼能否理解状态与下一步。

### 2. 抽屉响应式规则存在计算歧义

证据：提案规定侧栏 192、抽屉 360，主内容不足 560 时覆盖。980 宽窗口并排后剩 428；820 宽剩 268，均未扣正文边距。视觉板只给独立抽屉样例。

建议：明确按“扣除侧栏和抽屉后的可用主区宽度”判断。若 560 指包含边距的主区，1120 为理论并排下限，实际还需计入结构边界；若指正文净宽，还要加左右内边距。分别画出 820、980 的覆盖态及 1440 的并排态，并说明非模态查看与模态编辑的焦点、背景交互区别。

验证：临界宽度前后缩放，不来回跳动；关闭后焦点返回；被覆盖区域不能误触。

### 3. Provider 行的操作含义不够直观

证据：视觉板的 Codex 行同时放说明、配置路径、事件计数、旧 Hook 停用标签和电源图标。

判断：状态、技术说明和动作混在一起；仅从图中不能知道电源按钮控制旧 Hook 还是当前接入。此项不是对现有按钮实现的判定。

建议：名称与当前状态形成第一层；路径和事件计数为第二层；将现有主要动作写成准确动词，次要动作归入有名称的更多菜单。只有后端已有能力才能展示对应动作。

验证：长路径、多 Provider、禁用及异常状态下，动作仍可见且含义唯一；键盘可到达全部操作。

### 4. 概念图尚未证明状态系统成立

证据：视觉板主体为浅色正常态，暗色只有色块；没有真实控件的 hover、focus、disabled、error、loading 对照。提案明确承认静态颜色检查不覆盖实际叠加背景。

建议：补一张完整暗色页面，以及按钮、输入框、导航的状态矩阵。重点检查选中叠加焦点、错误字段聚焦、禁用文字和浮层边界。琥珀品牌强调与警告必须通过文字、图标和形状区分。

验证：在实际组件上测量对比度并走键盘路径；不能用生成图的色块代替验证。

### 5. 平铺方向正确，仍需收敛装饰权重

证据：视觉板取消嵌套卡片，但摘要竖线、区块横线、标题图标与粗体同时存在，导航选中块也较醒目。

建议：保留壳层的连续结构分隔线；正文优先用间距和标题分组，减少重复装饰。保留 Sand/Amber 和现有 Lucide；是否减少某条内容分隔线，需在多行内容上比较，不机械移除。

验证：亮暗主题下比较当前稿与减弱装饰稿，检查分组仍明确、主要内容更容易扫描。
