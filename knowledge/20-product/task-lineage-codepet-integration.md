# 任务谱系接入 CodePet 的实施评审

> 后续实现：用户随后要求完成六项桌面集成，已在同一隔离分支加入配置、Skills、工作区、异步接口和脏状态调度。现行行为见 [任务抽取运行时](../10-architecture/task-extraction-runtime.md)。下文保留评审时快照，其“尚需”不代表全部仍未实现。

## 背景

2026-09-10 用户在查看真实任务图及离线压缩包后，要求评估如何集成 CodePet。本次对主工作区与隔离分支源码、现有 Gateway 规约及真实试跑记录进行核对。本文是接入评审，待办项不代表已经实现。

## 目标

在 CodePet 桌面端形成“选择已有 Codex 来源 → 分析最近两天 → 查看任务 → 回溯原文 → 继续线程 → 人工验收”的闭环。复用现有 Svelte 组件和 Rust 领域服务，HTML 保留为离线导出形态。

## 非目标

本期不要求手机端同步交付，不新增独立网站、服务器或数据库，不把日志推断成任务完成，也不把一次导出的 JSON 当作应用实时数据库。

## 实现路径

### 1. 桌面入口与页面

沿用已接入的“任务”导航。初始显示本地结果，再提供“分析最近两天”，由后台完成扫描和有界抽取。来源使用“连接”里已经配置的 Codex 实例。将模型、预算、后台开关收进任务设置，主页面保留范围、进度和暂停/重试入口。当前尚需手动先扫描再抽取；将这两步合成用户动作时仍保留两个可恢复的后端阶段。

图、泳道、消息证据和人工验收复用现有组件。应增加候选任务的改名与合并能力，并独立保存人工修改，后续抽取不能覆盖。当前只有完成/重新打开，没有名称与任务边界校正，49 项候选中存在过细拆分或重复的风险。

### 2. 模型与成本配置

读取已有 Claude Provider 选定的运行时，显式绑定用于摘要的 Claude 实例及其数据目录。当前多 Claude 实例直接报错，需要选择绑定；模型为自由文本默认 haiku，实际模型必须继续展示。

应用目前硬编码单批 $0.10，真实离线试跑使用 $0.25，并曾反复触发预算耗尽。需要把单批预算与总运行预算持久化为统一配置，减少中文批次/候选摘要过大时的输入，预算耗尽后暂停并说明原因，不自动同参重试或切换高档模型。失败批次也可能收费；目前只有最近成功批次信息，成本展示不能称为总费用。

保持最近 48 小时、仅 user/assistant 正文的输入边界；工具执行与 reasoning 排除。长消息当前截取 2500 字符，需明确提示未分析全文，后续若改分段抽取要增加片段游标，不能在处理首段后把整条消息当全文已处理。

### 3. 应用内闭环与状态

[Gateway 规约](../60-rules/gateway-turn-send-admission.md) 要求 turn.send 面向空闲会话。当前任务面板只检查 capability，发送按钮未按运行/审批状态禁用；需要复用已有准入规则，交互权冲突明确提示。不能自动强制接管。

发送超时或结果未知时先刷新会话，不能每次重试生成新请求 ID 后盲目重发。验收至少覆盖空闲发送、执行中发送、交互权冲突、已受理但回包丢失四种场景。成功发送后状态与新增消息通过现有 Gateway 快照/事件收敛；任务抽取保持独立的后台增量处理。

运行状态和当前 Git 均来自实际查询，缺失时显示未知。Git 只能说明当前工作区事实，不回填历史节点完成时的状态。人工完成与模型判断独立保存。

### 4. 数据与后台生命周期

沿用应用数据目录 `task-lineage/v1/<provider hash>`。当前后台每 15 秒扫描，页面关闭后仍运行、应用退出停止；初次不开启。待处理数量当前遍历标准化消息块，数据量增长后会重复读盘，应改为按块保存时间索引与近期队列；先记录真实耗时再验证优化。

本次真实数据保留在隔离产物目录。应用没有导入入口，不能直接把 `data.json` 放入应用目录就宣称可恢复。可选择在原生应用里重新抽取，或实现校验版本、来源身份、证据与游标的一次性导入。导入须保留来源隔离与人工状态，避免再次产生相同模型费用。

### 5. 手机端后续接入

当前命令是 Tauri 本地 IPC，手机端无法直接调用。若后续需要 Remote 查看任务，任务服务仍运行在 Host，新增 Gateway 任务查询/消息回溯/验收方法，更新 schema 并生成 TS/Dart SDK，再实现 Remote 页面。模型执行和 Codex 文件读取留在 Host。首期桌面接入不以手机改造为前置条件。

## 风险与验证计划

1. 多实例目录错配：两个 Codex 与两个 Claude 实例的隔离测试；核对输入来源、实际模型和存储目录。
2. 摘要失真或预算失败：用真实任务证据复核，覆盖长中文、重复任务和预算耗尽；配置重启保持，失败不会无限重试。
3. 发送重复或误接管：验证运行/审批状态、writer 冲突、超时恢复；不把模拟 IPC 通过当原生链路通过。
4. 后台重复抽取：重启、暂停、文件重写、人工修改期间模型返回的回归；记录无新增时读盘耗时。
5. 发布回归：运行领域测试、前端构建及定向 UI QA、Tauri check 后启动分支应用，验证入口→分析→证据→继续线程→人工验收→重启保留，再合并构建。已有 27 项全仓 TypeScript 基线诊断需单独管理。
