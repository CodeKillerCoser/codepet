# 全局 UI 视觉基础提案

状态：视觉方向已确认（2026-09-08），尚未应用到生产界面。正式可交互视觉稿：[macOS](../../design/ui-foundations/visual-macos.html)、[Windows](../../design/ui-foundations/visual-windows.html)；可编辑源稿为 [visual-source.html](../../design/ui-foundations/visual-source.html)。用户确认导航与顶部工具栏共用背景、右侧大圆角内容面板，并要求压缩品牌区、减淡边框和阴影。旧 [visual-board.png](../../design/ui-foundations/visual-board.png) 仅保留为历史探索，不再作为实现依据。

## 现状与目标

现有主题位于 `frontend/lib/theme/tokens.css`，已有 primitive → semantic → component alias → asset 分层和亮暗主题；图标依赖已使用 `@lucide/svelte`。问题在于布局、字体用途、表面层级和颜色使用缺乏共同约束，不能仅靠换色解决。

目标是建立一套适用于主窗口及浮层的视觉语言：紧凑、安静、有少量温度。桌宠图案、通知业务和页面内容不在本轮重设计范围。

## 1. 骨架：共享壳层背景与圆角内容面板

窗口顶部为共享工具栏，下方为左侧 Sidebar 和右侧 Main。工具栏与导航共用连续的浅灰背景，导航右侧不画贯穿窗口的分隔线。Main 是一个独立的 16px 圆角面板，页面标题栏和正文一起位于面板内；右侧和底部距窗口边缘 8px。内容面板不使用阴影，边框仅作极轻的辅助轮廓，主要通过背景差区分壳层与内容。

以下尺寸均为逻辑 px，不是 Retina 截图像素。基准窗口 980×700，验证下限沿用现有 820×600。

| 区域 | 尺寸与布局 | 滚动／收缩规则 |
| --- | --- | --- |
| 共享工具栏 | 视觉稿高 40；横跨窗口，与导航背景一致 | macOS 左上角红黄绿；Windows 右上角最小化、最大化／还原、关闭；遵循各平台原生控制边距，交互区域不得成为拖拽区域 |
| 左侧导航 | 宽 192；Code Pet 品牌行高 36、行高 24、上下各 6、左右 20，仅展示文字；导航行高 36、行间距 4、左右内边距 12 | 导航可收起，收起后保留页面切换入口；底部辅助区固定；不增加新导航项 |
| 右侧标题／操作栏 | 圆角面板内部高 52；左侧页面标题，右侧现有页面操作；两端内边距 24 | 独立固定行，不在内容滚动容器内；标题只出现一次；操作多时进入溢出菜单 |
| 内容区 | 剩余全部空间；边距 24；820 宽时边距 20；区块间距 24，区块内部 12–16 | 单一主要纵向滚动区，禁止页面和大卡片重复滚动 |
| 宽屏 | 导航保持 192；表单内容最大宽 960，列表／表格可填满 | 不无限拉宽输入框；不通过放大字体填满空间 |

窗口控制按平台实现：macOS 使用原生 traffic lights，不显示 Windows 右上角按钮；Windows 不显示红黄绿。视觉稿中的窗口控制仅为位置示意，不能替代原生行为验证。业务调用采用统一窗口控制接口，平台差异集中在壳层／平台实现，不能散落到页面。Codex 参考仅用于壳层布局，不新增分享或导航历史等业务操作。

右栏内部为 52px Header 和剩余高度的 Content。仅 Content 设置 overflow-y:auto；Header 不参与滚动，其底部细线仅在圆角面板内部延伸，不连接窗口边缘。正式稿面板描边为浅色 #21201c08／深色 #ffffff08，Header 分隔线为 #21201c0a／#ffffff0a，面板 box-shadow:none。必要输入边界、焦点环不随装饰线一起减淡。生产实现应把这些角色映射到现有主题 token。

页面只提供标题、操作槽和内容槽；导航、滚动容器、Toast 宿主与浮层由壳层统一管理。详情抽屉不应成为每个页面自行创建的第二套侧栏。

| 浮层 | 规格 | 行为 |
| --- | --- | --- |
| 模态弹窗 | 常规宽 420，复杂表单 560；最大宽为窗口减 48，最大高 80%；边距 24；标题及底部动作固定，正文滚动 | 同时仅一个；焦点限制在内部，关闭后归还触发点；Esc 可关闭，有未保存修改时按业务确认 |
| 右侧详情抽屉 | 宽 360、不超过主面板宽度；位于面板 Header 下方，拥有独立标题和正文滚动 | 并排时按扣除侧栏、外边距、边界和抽屉后的主区宽度判断，至少保留 560，否则覆盖；并排无阴影，覆盖仅轻微阴影；非模态查看无 scrim，模态编辑使用 scrim 与焦点限制 |
| Toast | 右下距边 20，宽 320、最大为窗口减 40；最多显示 3 个，间距 8 | 普通提示 4 秒，悬停／焦点时暂停；需用户动作的消息不能自动消失，也不能只依赖 Toast 保存 |
| 菜单／Tooltip | 菜单行高 32、最小宽 160；Tooltip 宽不超过 280 | 靠近触发点且避让窗口边界；Tooltip 不承载交互操作 |

Toast 默认中性背景、状态图标和一句正文，不做大块红绿背景。模态开启时普通 Toast 延后，相关反馈放在弹窗内部。

## 2. 字体：按用途选角色

UI 字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。代码／路径：`"SFMono-Regular", Consolas, "Liberation Mono", monospace`。取消 SF Pro Rounded 作为全局首选；遵循系统字形，不额外下载字体。

| 字体角色 | 字号／行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| page-title | 16／24 | 600 | 固定标题栏中的页面标题 |
| section-title | 14／22 | 600 | 内容区块标题 |
| body | 14／22 | 400 | 正文、说明 |
| label | 13／20 | 500 | 导航、字段标签、按钮 |
| body-strong | 14／22 | 500 | 行标题、需要强调的正文 |
| caption | 12／18 | 400 | 辅助信息、时间、统计说明 |
| metric | 24／30 | 600 | 少量统计数值，启用 tabular-nums |
| code | 12／18 | 400 | 路径、端点、命令 |

字重仅使用 400、500、600；不使用 480、520、620 等细碎角色。中文不加字间距，不用大写英文眉题装饰每个区块。图标与文字基线对齐；路径单行省略并可查看完整内容，说明正文允许自然换行。禁用文字仍须可辨，不使用整行 opacity 连同状态一起淡化。

## 3. 色值：语义 token 与主题切换

使用项目已安装的 `@radix-ui/colors` 3.0.0：Sand 中性色、Amber 品牌强调，Grass／Tomato／Blue 状态色，Black Alpha 遮罩与阴影。不自制 primitive 色板；现有 Radix 依赖中补用 Sand 和 Grass 即可。

原始亮／暗映射保存在 `design/ui-foundations/color-tokens.json`，每主题包含 39 个语义色值及对应 Radix 色阶来源。`node design/ui-foundations/create_tokens.mjs` 从本地依赖重新解析映射并检查对比度。该文件保留早期配色快照，尚未纳入最终稿的共享壳层与轻描边。最终稿新增壳层浅色 #f0f3f6／深色 #1c1e21、内容浅色 #ffffff／深色 #141516；以本节及正式稿为准，接入生产主题时同步映射并重新验证，不直接沿用旧对比度结论。

| 类别 | 语义角色 |
| --- | --- |
| 表面 | bg.canvas、sidebar、surface、subtle、overlay |
| 文本 | text.primary、secondary、muted、disabled |
| 边界与图标 | border.subtle／strong，icon.primary／secondary |
| 交互 | interaction.hover／pressed，selection.bg／fg／indicator |
| 强调 | accent.solid／hover／pressed／onSolid／text，focus.ring |
| 控件 | control.bg／border／disabledBg |
| 状态 | status.success／warning／danger／info／neutral，各有 bg 和 fg |
| 浮层 | scrim、shadow |

默认、悬停、按下、选中、禁用和键盘焦点使用各自语义；焦点不是选中。浅色强调按钮采用琥珀底＋深字，不用黄底白字。正文文字配对要求至少 4.5:1；必要控件边界与焦点指示要求至少 3:1。低对比 border.subtle 只能作辅助分隔，不能作为唯一控件边界。

主要映射：canvas→Sand 1，sidebar→Sand 2，hover→Sand 4，正文→Sand 12，辅助文字→Sand 11，分隔→Sand 6，必要控件边界→Sand 9；选中→Amber 3／12，强调按钮→Amber 9／10＋固定 light Sand 12 深字。状态提示采用对应色系 3 阶底色＋12 阶文字，以满足小字号对比度。

纯色值以 Radix 库为准，JSON 保存解析快照和映射，不形成第二套色板。按下态与默认态可共用 Amber 9，通过轻微内描边反馈，无需为了每个状态新增颜色。

色板不直接按位置命名。生产接入继续沿用现有主题层级，由 `--app-*` 别名指向语义色，组件中不写裸色值。亮暗主题使用相同角色名；用户自定义宠物／气泡色保持为独立数据。固定第三方品牌图标保留原图，不强行染成琥珀。

## 4. Icon：沿用 Lucide

沿用 `@lucide/svelte`，圆端点线性图标，统一 strokeWidth=1.75。导航 18px，控件 16px，空状态 28px；用尺寸而不是更粗的线强调层级。

图标跟随文字语义色。侧栏品牌位只显示 Code Pet 文字，不放 App 图标；黑猫图标继续用于应用安装图标。导航功能图标保留，Provider 标识可以使用其真实资源；不将 emoji、实心图标和线性图标混用于普通操作。图标按钮热区至少 32×32，有可访问名称和 Tooltip；移动触控适配至少 44×44。

## 5. 配色方案：控制颜色用量

色值回答“具体是什么颜色”，配色方案回答“颜色用在何处、有多大面积”。本方案为暖中性底色＋炭黑文字＋低饱和琥珀点缀，暗色对应石墨底色，保持同一品牌气质。

- 页面大面积使用中性色；琥珀仅用于选中、主动作、焦点和必要强调，同一视口强调色面积目标不超过约 5%。
- 每个独立任务区域至多一个强主按钮；次要按钮用中性样式。
- 红绿蓝只表达错误、成功和信息，小图标、标签、细提示条优先；不为普通卡片分配彩虹背景。
- 错误字段使用 danger 边界＋图标＋文字，不只依赖颜色；严重操作的确认按钮才采用危险强调样式。
- 数据可视化未来若需分类色，应单独定义 chart 色板，不能直接把状态色当装饰色。

## 6. 风格：平铺为主，阴影只表达浮起

层级建立顺序：间距 → 字体 → 分隔线 → 轻微底色 → 阴影。页面内容直接铺在主表面；相关字段按组排列，统计数据可使用一条分组带。独立、可单独操作的实体才使用卡片；卡片内不再套同类卡片。

| 基础参数 | 规范 |
| --- | --- |
| 间距 | 4、8、12、16、20、24、32；主区边距 24 |
| 控件 | 默认高 32；密集列表行 40，含辅助信息的行 56 |
| 圆角 | 主内容面板 16；输入／按钮／导航 6；必要的内容容器 8；弹窗／菜单／Toast 10 |
| 描边 | 1px；焦点外圈 2px，offset 2px |
| 阴影 | 内容区、导航、普通卡片无阴影；菜单／Toast `0 4px 16px shadow`，弹窗 `0 12px 40px shadow` |
| 层级 | 内容 0，固定栏 10，详情抽屉 20，Popover 30，scrim 40，模态 50，模态内 Popover 60，Toast 70，Tooltip 80 |
| 动效 | 悬停 120ms；抽屉／弹窗 180ms ease-out；reduced-motion 时关闭位移，仅保留即时状态变化 |

禁用 grid 背景、装饰渐变、重阴影。壳层统一承载一个大圆角主内容面板；页面内部保持平铺，不重复嵌套整页卡片。圆角与留白不按每个页面单独发挥。

## 实现边界与验证路径

- 壳层：`frontend/App.svelte` 及其布局样式，负责结构和滚动。验证 820×600、980×700、1440×900，以及长标题／多操作的溢出；滚动时标题栏固定，工具栏与导航背景连续，圆角面板没有重边框／阴影，品牌行保持 36px；分别验证两平台原生窗口控制。不得改动页面内容定义。
- 主题：`frontend/lib/theme/`，负责现有语义色及 component alias 的迁移；保持系统／亮／暗选择。验证正文、控件边界、选中、禁用与焦点配对。
- 字体／共享控件：先统一角色与尺寸再迁移页面，验证中文／英文／路径、键盘焦点、动作可见性；不要仅靠截图判断交互完成。
- 浮层：验证焦点进入与返回、Esc、遮罩、滚动锁、窗口边缘避让和 Toast 堆叠，不允许抽屉遮挡后仍误点底层操作。
- 自动化：颜色脚本检查亮暗文本对比度；落地后运行 `npx vitest run frontend/styles.test.ts` 及被修改控件的相关测试；搜索主题目录以外新出现的裸色值。

### 2026-09-08 主窗口框架落地

目标是更新框架、布局、配色、字体和间距；页面字段、文案、业务操作及排序保持现状。与视觉稿提交 `ca316e3` 逐字比较，`App.svelte` 的 Agent 至事件页产品模板完全一致，脚本除工具栏导入和侧栏折叠状态外完全一致。

- `frontend/App.svelte`：增加全局工具栏和固定内容标题区，内容独立滚动；更新弹窗纳入主题祖先。
- `frontend/main-window.css`、`frontend/lib/theme/main-window.css`：仅在 `.main-theme` 内覆盖共享样式，保留桌宠窗口和用户自定义气泡色。事件页取消二次内边距，搜索框、原生滚动条跟随主题；主动作禁用态采用中性色。接收／错误标签使用状态色 3 阶背景和 12 阶文字，避免旧混色小字对比度不足。
- `frontend/lib/WindowToolbar.svelte`、`windowChrome.ts`：平台检测和窗口调用收敛于适配层，支持折叠、Windows 窗口动作、最大化状态订阅与清理；异步错误进入现有提示。
- `src-tauri/src/platform/main_window.rs`、窗口配置：macOS 采用 Overlay 和隐藏标题，保留系统红黄绿；托盘重建主窗口沿用同样配置。`capabilities/main-window.json` 的新增权限仅属于主窗口。

验证证据：生产构建通过，styles／connections／windowChrome 共 42 项测试通过。使用隔离 Tauri 数据的生产页面检查了 820×600、980×700、1440×900，覆盖五个导航页、亮暗主题、导航折叠和键盘焦点。长个性化页面滚动 3102.5px 时，标题区仍位于 y=41，高 52px；内容无横向溢出。品牌行 36px、侧栏 192px、内容圆角 16px，无面板阴影。Windows 分支按钮位于右上方；macOS 浏览器分支保留 70px 原生按钮空间且不生成 Windows 控件。测试桥接不连接真实设置或设备。

最终生产页面的计算样式抽查（包含浏览器采用的 Display P3 色值，按线性亮度计算）：正文／辅助文字／导航选中／接收状态，浅色依次为 16.29／6.05／10.47／10.87:1，深色为 15.73／8.72／12.98／11.85:1，均超过小字号文字 4.5:1。此抽查不冒充全部状态穷举，也不替代历史颜色文件。

命令：`npm run build`；`node node_modules/vitest/vitest.mjs run frontend/styles.test.ts frontend/connections.test.ts frontend/lib/windowChrome.test.ts --maxWorkers=1 --minWorkers=1`；`git diff --check`。普通 `cargo check --manifest-path src-tauri/Cargo.toml --offline -j 2` 因缺少未生成的 `resources/provider-sdk` 停在打包资源检查。临时设置 `TAURI_CONFIG={"bundle":{"resources":[]}}` 后同一命令通过，确认 Windows 源码及能力配置有效；这不代表完整打包通过，正式配置未修改。

剩余验收：真实 Windows／macOS 窗口的拖动、最大化、关闭后托盘重开与系统缩放，以及 macOS 全屏和红黄绿命中区域；当前浏览器桥接只能证明 DOM 分支和动作路由，不能代替原生实机。正式打包需先生成 Provider SDK 资源。生产浮层的焦点／Esc 行为未作功能改动，仍需在真实配对和更新场景复核。
