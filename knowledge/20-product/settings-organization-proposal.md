# 主窗口与设置分区整理

## 背景

2026-09-13 使用 Computer Use 检查本机运行的 Code Pet。安装版有任务、Agent、连接、用量、个性化、事件六个主导航，以及顶部设置入口。初始工作区位于旧提交 deb34110，只有四个主导航；实施前已在本工作区基于 v0 的 ea9ee1e1 新建 codex/settings-organization 分支。下表保留调整前的实机观察，后续章节描述本分支实施结果。

## 目标

将日常工作与长期配置分开，消除个性化长页和 Agent 配置分散问题。

## 非目标

不改变后端 API、数据存储格式、接入权限与执行能力；不启动真实抽取、切换运行时、配对设备或发送通知。未替换已安装 App。

## 实现路径

按用户确认的方向，主导航保留任务、连接接入、用量、宠物制作四个入口。设置沿用现有入口与侧栏切换模式，提供明确的返回工作区入口。

| 主导航 | 内容 |
| --- | --- |
| 任务 | 会话与任务查看、搜索、扫描、手动整理、整理范围与运行历史 |
| 连接接入 | 合并现有 Agent 与连接入口，分为活动接入、本机运行时、远程设备三个子页；保留来源开关、状态、运行时检测与路径选择、设备配对与权限管理 |
| 用量 | 数据来源、时间范围、粒度、模型筛选、分组与统计结果 |
| 宠物制作 | 宠物库、选择与管理宠物、图片抠图导入、像素化调整和预览；基于现有功能整理，不假定已有绘图或动画制作工具 |

| 设置分区 | 内容 |
| --- | --- |
| 通用 | 开机启动；数据与存储（安装目录、数据目录、工作目录说明、宠物资源目录） |
| 外观与桌宠 | 应用主题、窗口透明度；任务气泡颜色、渐变、边框、动画；互动反应音。宠物制作和管理在主页面完成 |
| 通知 | 本地提醒的触发事件、音色、试听、自定义音频、重复间隔、静音时段；机器人渠道、独立触发规则、模板 |
| 任务抽取 | 抽取执行 Agent、实例、模型、推理强度、Skill、提示词、定时规则；高级执行选项折叠展示 |
| 诊断 | 现有事件日志及其搜索、来源过滤、暂停刷新、详情 |
| 关于 | App Logo、原生 App 版本、当前前端资源版本、检查更新及结果反馈 |

任务页保留来源选择、扫描、手动整理、整理范围、运行历史和结果查看；用量页保留全部分析筛选。它们控制当前工作，不应收到设置。任务页的抽取状态旁直达设置中的任务抽取；缺少运行时及用量错误直达主页面“连接接入”的对应运行时。宠物制作页可链接外观与桌宠设置，资源目录修改统一归数据与存储，避免重复表单。

每个设置只保留一个完整编辑位置。机器人模板默认折叠，自定义音频选中后再显示文件配置。日常状态使用“正在接收活动”“可执行任务”等用户语言，Provider/Harness/路径移入详情，但底层状态仍需分别表达，不能错误合并。

## 涉及模块

- 主窗口导航与页面：承担分区、返回路径、配置直达和滚动状态。由 `frontend/App.svelte`、`frontend/lib/MainNavigation.svelte`、`frontend/lib/navigation.ts` 实施。入口分组、页面标题与导航历史使用同一组路由定义。
- 设置存储与通知：迁移 UI 时保留字段及通知触发语义，特别是本地声音与机器人规则的区别。
- Provider 与远程设备：合并入口但保留生命周期和权限边界。
- 桌宠窗口：只增加必要快捷入口，保留当前只读任务呈现。

## 风险

- 配置隐藏后难找：业务页保留直达对应分区的入口，人工验证从错误到配置再返回的路径。
- 安装版与源码不一致：实施前定位对应提交和模块；尤其数据目录，安装版提示只切换且不复制清空，旧源码文档描述迁移复制，不能混用。
- 切页丢失未保存配置：检查保存提示和草稿生命周期，分别测试自动保存控件与任务抽取显式保存表单。
- 小窗口长表单和焦点丢失：按实际 982×730 窗口及更窄尺寸检查滚动、键盘焦点和操作可见性。

## 设置样式与关于页（2026-09-13）

根据用户提供的 Codex 设置截图，设置页采用标题在外、内容在圆角细边框卡片中的分节形式。设置行左侧为选项及说明，右侧为值和控件；窄窗口允许值换行，路径完整折行。任务抽取细分为数据来源、抽取 Agent、定时任务和高级设置，继续使用显式保存并保留跨页草稿。通知机器人、渐变编辑器沿用原保存逻辑。

`HorizontalTabs.svelte` 统一连接子页导航，提供 tablist/tab/tabpanel 关联、单一 Tab 停靠点、左右键循环以及 Home/End 跳转。切换子页时焦点留在 Tab，其他页面跳转仍聚焦标题。`SettingsRow.svelte` 与 `main-window.css` 负责公共选项行；`AboutSettings.svelte` 承担品牌与版本信息。原生版本由 Tauri getVersion 读取，失败显示不可用；资源版本从构建时 package.json 导入，与 webcontent 清单使用同一来源，不借用原生版本，也不依赖生产协议未暴露的 manifest.json。

验证：前端 29 套件、196 项测试通过；生产构建成功。使用真实 App 的模拟 IPC 页面检查 1280×720 与 600×730、浅色/深色、横向导航键盘切换及内容焦点、路径与操作按钮、机器人配置、抽取草稿保留、两个不同版本的展示和检查更新反馈。原生版本读取权限沿用 core:default。未执行原生安装、真实更新下载或外部机器人发送。
