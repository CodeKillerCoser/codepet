# 网络变化时的连接恢复与当前通道展示

状态：2026-11-07 方案评审，未实施。按 living-dev-doc-writer 记录源码证据与边界。本轮不改连接逻辑，不改 VPN/路由，不部署版本。

后续核心设计与实施分期见 [连接引擎](connection-engine.md)。本文保留现状证据与需求演进；接口、状态机、交接和验收以核心设计为准。

## 背景与目标

用户反馈桌面同一手机同时出现中继与 IPv6，且手机离开局域网后没有自动切换。目标是网络变化后自动重新选择可用通道，界面准确显示当前业务连接，保留现有四路并行原则。非目标是长期保持四条业务连接、强制绕过 VPN、保证任意网络可达或实现完全无中断迁移。

## 证据与现状

- Host `remote/connections.rs` 按连接 ID 保存活动对象，Drop 才移除；`RemoteDeviceList.svelte` 遍历设备全部 connections。这里没有历史列表，也没有明确的“当前业务连接”选择。旧链路未清理与新链路重叠是可能原因；缺少用户本次连接 ID/时间线，不能认定泄漏或双重业务发送。
- Remote `routed_rtc_transport.dart` 首个 transport.connect 成功即选中并取消其他候选，早于 Gateway 身份握手。选中之后不主动重新竞速；赢家 events.onError 向上传递，但 onDone 只完成竞速等待器，在线后的关闭可能不能立即通知会话。
- `DeviceSession` 已有可重试错误后的自动恢复（1/2/5/10/30 秒，最多五次）；reconnectSignals 由 App 注入 mDNS 发现更新，只在 failed 且尚未耗尽次数时生效，在线状态忽略。失败清理还等待旧 client.close，需要验证并限制卡住的清理。
- `NetworkDiagnosticsBridge.kt` 只提供网络快照，没有持续监听。RTC disconnected 仅记日志，failed/closed 才中止。WSS 协议 ping 间隔 20 秒，Gateway 心跳间隔 20 秒、单次超时 10 秒、失败窗口 60 秒，静默断网可能较晚才被判定失败。

## 统一优先级与适用场景（用户补充要求）

本文此处及下文更新替代此前“只恢复故障、暂不升级健康链路”的建议。首次连接、网络变化、断线重连必须使用同一个 ConnectionCoordinator，按以下顺序选择健康且通过身份校验的通道：

1. LAN / 可达地址上的 WSS：包含家庭局域网、企业 VPN、Tailscale 等组网地址。
2. WebRTC IPv6 直连。
3. WebRTC IPv4 直连。
4. WebRTC 中继。

IPv6/IPv4 可借助信令服务协商，但通道类别以实际业务数据所走的 ICE pair 为准。LAN 表示 App 的地址连接方式，不承诺 VPN/组网产品内部一定没有转发；仅开启 VPN 也不能证明目标可达。所有路径继续校验相同的设备身份。

优先级不改变并行原则。无连接时四路同时尝试，先可用先提供服务；多个候选已就绪则选最高优先级。中继先成功时可以先用，保留更高优先级尝试，等 IPv6 或 LAN 确认健康后自动升级。低于当前优先级的候选及时释放，不长期保持四条业务连接。

网络变化后：旧连接失效则立即恢复竞速；旧连接仍健康则保留服务并探测更优路径。LAN 恢复后自动从中继或 WebRTC 切回 LAN，不必先人为断开。健康的同级路径保持稳定，不按瞬时网速跳动切换；“最优”指符合上述优先级的可用路径，并非绝对带宽最大者。

更高优先级需稳定确认、事件去抖和切换冷却，故障恢复不受冷却限制。阈值留待实测。当前不是最高优先级且候选已结束时，保留有界、退避的更优路径复查，结合新地址发现、前台恢复及网络事件唤醒，覆盖“电脑网络恢复而手机没有事件”的情况。后台尊重系统生命周期，不承诺被系统挂起时实时迁移。

## 基础模块与触发源解耦（用户确认的职责边界）

连接模块不识别“首次连接”“网络变化”“用户重连”等业务场景。这些只是外层触发源：App、网络观察适配器、前台生命周期和重连调度将事件转换成相同的连接协调请求。禁止在模块内按触发源名称编写不同的选路策略。

基础模块包含三项能力：

- 通道选择与建立：管理目标设备的候选、并行建立、优先级、唯一活动通道、升级/降级与旧连接释放。
- 健康度观测：消费各通道适配器的存活、探测响应、延迟、超时、关闭及背压信号，形成健康状态并触发同一套连接协调。网络有流量或速率为零都不能单独证明健康或断线。
- 传输统计：统一计数、窗口速率、活动通道统计快照与连接代次。统计不绑定页面，不重复累计新旧通道，也不以实际吞吐冒充可用带宽。

建议公共契约为 `reconcile(target, policy)`、`disconnect(target)` 和 `watch(target)`：reconcile 表示“确保目标连接可用并按策略选择最优路径”，并非每次调用都重建。模块根据当前状态决定保持、探测、建立、切换或退避；重复请求合并，每目标至多一轮协调任务。disconnect 是显式期望状态，撤销进行中的建立/优化任务；迟到回调不得复活连接。watch 输出连接阶段、实际通道、健康状态、速度和累计量，所有 UI 共用这份事实来源。

目标、授权引用、候选地址与能力、优先级策略和资源预算是模块需要的输入。网络环境由统一端口提供最新快照，或由外层更新候选环境版本；模块不调用平台 API，也不需要知道是谁更新了环境。环境版本变化可使旧候选失效；身份/凭据改变必须由不同的授权代次隔离。仅用于排查的关联 ID 可以传递，但触发源名称只在外层日志记录，不参与策略分支。

外层不再各自运行重试算法，只决定何时请求协调以及目标应保持连接还是断开。连接尝试的退避、探测周期、健康失败处理与优化冷却由模块统一管理；平台允许的后台运行/暂停作为生命周期约束输入。授权撤销和业务会话恢复依然有独立边界：基础模块报告通道交接，应用层负责 Gateway 快照、订阅、未完成业务操作的处理，不把业务 RPC 重放塞进通道模块。

验收补充：不同触发源产生相同输入和当前状态时，模块决策相同；并发 reconcile 不重复建连；健康失败走同一状态机；断开后迟到任务不能复活；页面销毁不终止健康观测和统计，目标连接释放后才释放其资源。依赖检查禁止基础模块引用 UI、网络事件来源或具体平台实现。

## 推荐实施路径

新增应用层 ConnectionCoordinator，每目标设备一个实例，统一拥有首次连接、当前路径、更优路径探测、恢复调度和切换状态，复用现有竞速和传输。DeviceSession 保留 Provider、会话快照与业务控制职责，通过应用层接口参与交接，避免两个模块同时重试。平台适配器通过 NetworkEnvironmentMonitor 端口提供合并后的网络变化事件；上层不依赖 Android API。Host 确认业务连接归属与隔离旧代，UI 只读取协调后的状态。

1. 先补齐赢家关闭、心跳失败和清理超时的统一失败出口，以及旧 generation 不能覆盖新连接的测试。保持人工断开和撤销凭据不会自动复活。
2. Android 监听默认网络及相关可用网络的能力、地址、路由变化；前台恢复时补一次核查。事件合并去抖，按 networkGeneration 隔离旧任务。同一变化只启动一次恢复，不因手机信号强弱更新重复建连。
3. 网络变化只是重新评估的触发器，不等于目标不可达。当前路径明确丢失则立即启动四路竞速；只是默认网络变化时，保留可用旧连接，做有界健康核查。VPN 内网没有公网验证也可能可达，不按 INTERNET/VALIDATED 单独否决；不强制绑定到隧道外网络。Android 默认网络 onLost 不等于旧物理网络彻底消失，按回调语义区分。[官方说明](https://developer.android.com/develop/connectivity/network-ops/reading-network-state)
4. 每轮并行尝试 LAN、IPv6、IPv4、relay，按“先可用、再升级”策略收敛到最高可用优先级。候选允许身份握手与健康核查，不能重复发送用户 RPC 或投递业务事件。
5. 不直接在有未完成 RPC 的 transport 下替换 socket。通过明确的会话 generation 完成重新握手、订阅与快照同步；旧代迟到响应不可更新新代。已发送而结果未知的写操作保留“结果待确认”，不自动重发创建会话、发送消息或审批；Host 正在运行的任务不因客户端重连而停止。
6. 离线状态等待网络事件，失败时保留有限退避，网络真正变化/前台恢复允许重新获得尝试预算。避免五次耗尽后只能手动重连，也避免无网络时持续高频探测。

健康路径主动升级时先准备新连接，成功后短暂冻结新写请求，等待已发 RPC 在有界窗口内结束，再提交活动代次、恢复快照与订阅，最后关闭旧路径。准备失败则继续旧连接。旧连接健康但写请求未结束时延期优化，不能为升级中断未知结果的写入；运行中的 AI 任务不等于未完成 RPC，不要求整个任务结束才能迁移。切换确认丢失要查询或重试同一幂等代次，Host 拒绝旧代继续业务写入，避免双主。

## 桌面展示与连接归属

简单按最后创建时间、最大流量或 IPv6 优先挑一条连接都不能证明它是业务连接。应由 Remote 在选中并完成握手后明确确认当前连接，Host 按安装身份与逻辑会话管理递增代次及活动归属。切换确认必须幂等，旧代消息不能抢回归属；协议能力需协商，更新 schema/生成 SDK，不手改生成文件。

同一逻辑会话仅一个 active，可短暂存在 connecting/draining。主界面只显示 active；健康升级准备期间保留当前通道，可附“正在优化连接”，故障恢复时显示“正在重新连接”。确认交接后才更新通道与统计，旧连接有界退场。确有多个独立会话的旧端不得静默断开，兼容期明确显示“多个连接”，不伪称已确定当前通道。若实测证明只是清理遗漏，可先修生命周期；当前归属仍不能用展示层去重代替。

流量继续沿用本次物理连接口径，新连接归零。若未来需要跨切换累计，必须单独定义会话级计数与去重，不能把新旧瞬时速率简单相加。

## 模块、风险与验收

- Remote app/Android adapter：网络事件、前台生命周期和订阅释放。验证 Wi-Fi→蜂窝、蜂窝→Wi-Fi、VPN 开关、企业 VPN LAN 可用和快速抖动。
- 应用层协调器/DeviceSession：重试唯一所有权、代次与业务恢复。验证五次失败后网络恢复、手动断开、凭据撤销、长任务与结果未知写操作。
- race/各 transport：赢家正常关闭、静默丢包、探测超时与清理不阻塞新轮次；验证 LAN 不通时 IPv6/relay 并行成功，只有一个业务发送者。
- 优先级与升级：验证中继最先完成后自动升级 IPv6、LAN 最晚恢复后切回 LAN；多个同时可用选最高优先级；高优先级抖动、准备失败或有未完成写请求时不会反复切换或重复写入。三种入口须使用同一套策略测试。
- Host presence/协议/桌面 UI：明确 active 归属、旧连接退场与兼容。验证同手机快速重连、新旧代乱序和多个独立会话，UI 不显示过期通道。
- 实机用路由器断上游但保留 Wi-Fi 验证“系统网络未变但业务不通”；用断 Wi-Fi 验证事件触发的恢复，不只在模拟器测断线。分别统计发现故障、选路、身份握手、恢复订阅耗时，恢复时间以实测为准。

## 诊断与未知项

只记录 networkGeneration、connectionGeneration、raceId、旧/新通道、触发原因、阶段耗时、active 确认及退场结果；同一状态不重复刷日志，保持标准纯文本。

当前反馈是否属于静默断网、正常关闭未上报、重试耗尽或清理卡住，尚无对应最新日志证实。桌面双通道持续时长、实际运行构建版本及两条连接归属也未知。以上方案先覆盖已确认缺口，再用实机时间线收敛参数，不将单一假设当作根因。
